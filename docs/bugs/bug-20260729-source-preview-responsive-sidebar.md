# Bug: source-preview-responsive-sidebar

**日期：** 2026-07-29  
**优先级：** 中  
**状态：** 待分析

## 复现步骤

1. 在主导游窗口中点击搜索来源或探索结果。
2. 打开网页预览面板。
3. 调整主窗口尺寸、切换不同显示器或改变系统缩放比例。
4. 观察网页预览面板与主窗口的相对位置、宽度、内容可读性和关闭后的恢复行为。

## 实际结果

当前网页预览面板的响应式布局无法提供类似 Viva 浏览器侧边栏的稳定体验：主窗口宽度变化、边界空间不足或显示器变化时，面板的尺寸与位置缺少清晰的停靠规则，网页内容区也没有一套面向窄侧栏的重排设计。

## 预期结果

网页预览应重新设计为“伴随主窗口的响应式侧边栏”，目标体验参考 Viva 浏览器侧边栏：

1. 有明确的左/右停靠边与固定的最小、理想、最大宽度；
2. 主窗口空间足够时，侧栏贴靠主窗口边缘且不遮挡关键对话区域；
3. 空间不足时，自动选择内嵌、覆盖式抽屉或紧凑模式，并保留可见的关闭与返回入口；
4. 跨显示器、缩放变化、窗口最小化/恢复时，位置计算稳定且不闪烁；
5. 预览顶部工具栏、网页内容、加载/错误状态均适配窄宽度；
6. 搜索来源与探索来源复用同一套侧栏布局和状态机。

## 影响范围

- `desktop/main/` 中来源预览窗口管理逻辑
- `desktop/renderer/src/main.tsx`（来源预览触发）
- `desktop/renderer/src/style.css`（主窗口与来源入口视觉布局）
- `tests/unit/source-preview.test.ts`（位置与尺寸规则）
- 搜索来源预览、探索百科预览、不同屏幕尺寸与多显示器场景

## 初步判断

待分析。当前实现以独立伴随窗口为核心，位置计算偏向“跟随主窗”而非“具有断点与模式切换的侧栏布局”。这属于交互与窗口架构重设计，不应通过零散 CSS 或单个偏移量修补。
