# Bug: explore-360-baike-inconsistent

**日期：** 2026-07-29  
**优先级：** 高  
**状态：** 已修复；自动化验证通过；人工未验收

## 复现步骤

1. 在设置中启用“探索”，并将百科来源切换为“360 百科”。
2. 完成一轮对话后点击“探索”。
3. 对比来源设置为“百度百科”时的探索结果、打开行为和预览表现。

## 实际结果

选择“360 百科”时，原实现只生成搜索页 URL，因此用户进入的是结果列表，而不是与百度百科类似的具体词条页。360 百科的具体 `/doc/<id>-<id>.html` 地址包含站点生成的数字 ID，不能仅由查询词安全推导；同时搜索结果可能没有准确词条或受到网络限制。

## 预期结果

在相同的对话与飞行上下文下，切换至“360 百科”后：

1. 探索仍可生成可点击的主题；
2. 服务先请求 360 百科搜索页，并仅从允许域名和 `/doc/<id>-<id>.html` 路径中解析与词条相符的真实页面；
3. 点击后应在来源预览面板中正常打开；
4. 若没有可确认的直接词条，保留搜索页作为明确的降级入口，不伪造词条 URL；
5. 多个主题解析到同一页面时应按规范化 URL 去重，并尝试同一词条的备用查询。

## 影响范围

- `src/discovery/exploration.ts`（探索主题生成与来源选择）
- `src/discovery/encyclopedia/`（百科来源适配器）
- `desktop/renderer/src/main.tsx`（探索入口与来源预览触发）
- 来源预览窗口及其 WebContents（网页内容容器）
- 使用非百度百科来源的探索用户

## 根因与修复

- 根因是把“站内搜索页”误当成了“具体百科词条页”；360 百科的具体页面 ID 必须通过搜索结果解析，不能由 AI 或前端猜测。
- `Qihoo360BaikeSearchPageProvider` 现在会读取公开搜索 HTML，按查询词和备用名称匹配真实 `/doc/` 链接，匹配不到或请求失败时返回原搜索页卡片。
- `EncyclopediaService` 对百科 URL 做规范化去重，优先保留不同的直接词条；重复时尝试备用查询，避免同一词条被多个主题重复展示。
- 当前实现和自动化测试已通过，但实际 Electron 来源窗口、目标网络和不同词条的人工打开体验尚未确认，因此保留“人工未验收”状态。

## 验证记录

- 已覆盖 360 百科直接词条、搜索页降级、备用查询和规范化 URL 去重测试。
- 已通过 `pnpm test`、`pnpm lint`、`pnpm typecheck`、桌面 TypeScript 检查和 `pnpm build`。
- 待人工验收：在真实 Electron 来源窗口中用“长沙”等词条确认优先进入 `/doc/` 页面，确认无准确结果时搜索页降级可用，并确认移动尺寸下的加载表现。
