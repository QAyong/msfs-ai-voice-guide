# Bug：来源入口缺失与伴随网页窗空白

**日期：** 2026-07-19

**优先级：** 高

**状态：** 已定位，待修复

## 复现步骤

### 问题一：联网回答没有结构化来源入口

1. 启动 Electron 桌面应用并连接 LiveKit Room（实时语音房间）。
2. 通过文字或语音询问“请联网介绍苏黎世湖，并给出来源”。
3. `searchWeb`（公开网页搜索工具）成功返回同时包含 HTTPS、HTTP 和空网站名称的混合结果。
4. 等待 Agent 完成回答，观察聊天面板。

### 问题二：伴随网页窗加载失败后保持空白

1. 在聊天中点击一个可打开的 HTTPS 链接，使应用创建来源伴随窗口。
2. 目标网站返回 HTTP 错误、网络连接失败、证书错误或加载超时。
3. 等待至少 15 秒，观察伴随窗口。

## 实际结果

### 问题一

- Agent 正文会写出“资料来源”及若干网站名称。
- 聊天面板收不到 `msfs.guide.sources`（导游来源数据主题）事件，因此不显示结构化来源入口。
- 用户无法从正文中的来源名称进入搜索结果预览或原网页，也无法判断这些名称是否来自成功工具调用。

### 问题二

- 来源窗口创建成功，但远程网页区域保持白色。
- 本地标题栏只显示固定文案“来源网页 / 仅加载 HTTPS 原始页面”。
- 界面没有真实域名、加载进度、错误原因、返回搜索结果、重试或系统浏览器打开。
- 用户无法区分网站拒绝访问、网络失败、应用错误或仍在加载。

## 预期结果

### 问题一

- 一次成功的搜索工具调用在对应回答下只生成一个“已检索 N 个网页来源”入口。
- `N` 等于逐条清洗、去重后实际可展示的来源数量。
- 点击入口后，伴随窗口按搜索原始排序展示网站身份、标题、搜索摘要、可选缩略图和发布时间。
- 单条 HTTP、空网站名称、无效图标或无效缩略图不得导致整批其他来源消失。

### 问题二

- 点击 HTTPS 来源后显示加载中状态和真实域名。
- 加载成功时显示隔离的原网页。
- 超时或失败时显示错误恢复页，并提供返回搜索结果、重试、系统浏览器打开和关闭。
- HTTP 或其他不满足应用内安全策略的来源只允许经校验后在系统浏览器打开。

## 影响范围

- `src/search/`（搜索服务模块）的原始响应标准化、逐条降级和来源数量语义。
- `src/agent/search-source-events.ts` 的工具输出解析与来源事件发布。
- `shared/guide-events.ts` 的来源消息契约。
- `desktop/renderer/` 的回答关联、单一来源入口和搜索结果预览。
- `desktop/main/index.ts` 的 `WebContentsView`（网页内容视图）加载状态、错误处理和白名单 IPC（进程间通信）。
- 用户对“已联网核实”声明的信任，以及飞行中快速判断来源的主要路径。

## 已确认根因

### 根因一：严格校验整批来源

`extractGuideSources()`（提取导游来源）先用包含严格 `guideSourceSchema`（来源校验规则）的数组 Schema 校验完整工具输出。该规则要求每一条来源都具有非空标题、非空网站名称和 HTTPS URL。搜索服务当前允许 HTTP URL，并会把缺失的网站名称标准化为空字符串。

当一次成功搜索同时包含有效 HTTPS 来源、HTTP 来源或空网站名称时，数组中任意一条失败都会使整个 `safeParse()`（安全解析）失败。函数随后静默跳过该工具结果，不调用 `publishData()`（发布数据），因此桌面端收不到任何来源。

真实搜索诊断已经确认：苏黎世湖查询返回 `status: "ok"`，同时包含可用的瑞士国家旅游局 HTTPS 页面、一个 HTTP 页面和一个空 `siteName`（网站名称）的页面，符合该整批失败条件。

### 根因二：远程网页失败没有状态通道

`showRemoteSource()`（显示远程来源）创建 `WebContentsView` 后直接等待 `loadURL()`（加载网页），但没有为远程 `sourceView.webContents` 注册加载开始、完成、HTTP 错误、`did-fail-load`（加载失败）、渲染进程退出或超时处理。`source:open` IPC 也没有把失败状态转换为来源 Renderer 可消费的结果。

当前来源 React 页面只有静态标题栏和加载占位；远程视图失败后没有状态可以替换白色内容区域。诊断使用的 `https://www.myswitzerland.com/` 根地址在沙箱外 GET 请求中返回 HTTP 406，而具体来源页 `https://www.myswitzerland.com/zh-hans/destinations/lake-zuerich/` 返回 HTTP 200。这说明观察到的空白由目标 URL 拒绝访问触发，但无限空白属于客户端缺少错误恢复的产品缺陷，并不表示所有来源页面都无法加载。

## 处理方案边界

1. 在 `src/search/` 逐条标准化和降级来源，向 Agent 与桌面端输出同一份清洗后集合；不能在事件层用一个脏结果否决整批。
2. 将聊天面板由多张来源卡片改为单一“已检索 N 个网页来源”入口。
3. 新增本地可信的搜索结果预览状态；字段映射和数量语义遵循 Spec-003。
4. 为远程网页建立显式状态机：`loading`（加载中）、`ready`（已加载）、`error`（失败）和 `timeout`（超时）。
5. 通过白名单 IPC 在主进程和来源 Renderer 之间传递经过校验的状态、真实域名和错误类别；不得向远程网页暴露 Preload 或 IPC。
6. 原网页和搜索结果预览在同一伴随窗口内切换；返回结果列表时恢复滚动位置。

## 验证要求

- 单元测试覆盖一批同时包含 HTTPS、HTTP、空网站名称、无效图标和无效缩略图的来源，确认保留其他有效来源。
- 单元测试覆盖来源数量使用清洗后实际列表长度，而不是供应商 `TotalDocCount`（总召回数量）。
- 集成测试覆盖工具调用、来源事件与正确 Agent 回答 ID 的关联。
- 主进程测试覆盖导航成功、HTTP 错误、网络错误、超时、重试、外部打开和返回搜索结果状态。
- 桌面端测试覆盖单一来源入口、结果列表滚动恢复、键盘焦点和错误恢复页。
- 真实 Electron 冒烟测试至少验证一个可正常加载的 HTTPS 页面和一个确定失败的页面；失败页面不得出现无限白屏。
