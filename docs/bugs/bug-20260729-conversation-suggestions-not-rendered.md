# Bug: conversation-suggestions-not-rendered

**日期：** 2026-07-29  
**优先级：** 高  
**状态：** 已废弃，不再采用

**处置：** 对话建议功能及其后续验收已退出当前产品范围，不再继续分析、实现或补充端到端验收。本文仅保留历史问题和旧实现背景。

## 复现步骤

1. 启动“云迹导游”桌面应用，并确认设置中的“显示对话建议”已开启。
2. 发送普通文本问题，或发送会触发网页搜索的问题。
3. 等待主 AI（大语言模型）完成正式回答。
4. 观察最新 AI 回答下方是否出现三条可编辑的下一步问题。

## 实际结果

主回答可以完成，但前端没有稳定显示对话建议。

已有日志证据显示，建议任务曾进入 `suggestions_started`（建议生成已启动），但旧实现没有记录“模型生成完成”“结果已发布”“前端已接收”等分段状态，无法确认故障发生在生成、传输还是渲染环节。

历史代码曾从 Agent（导游后端）通过 LiveKit 数据通道单向推送，改为“后端缓存、前端通过 `getConversationSuggestions`（拉取对话建议）RPC 主动拉取”。该替换不再属于当前采用范围。

## 预期结果

每次主 AI 的最终回答完成后：

1. 后端生成恰好三条建议并缓存；
2. 前端以最终回答为匹配条件拉取结果；
3. 收到 `ready` 状态后，在该最新回答下展示三条建议；
4. 若生成尚未完成，前端应显示明确的等待状态或在限定次数内重试；
5. 若失败或超时，应记录可定位的错误，而不是静默不显示。

## 影响范围

- `src/agent/guide-agent.ts`（导游 Agent 与建议生成、缓存逻辑）
- `src/discovery/suggestions.ts`（建议生成与 JSON 校验）
- `desktop/renderer/src/main.tsx`（前端建议拉取与渲染）
- `shared/voice-control.ts`（LiveKit RPC 协议）
- 所有完成问答后依赖下一步引导的用户场景

## 初步判断

历史判断：旧版的单向 DataChannel（数据通道）可能在发布或接收环节悬挂，且缺少确认日志。该问题及新版 RPC 方案均不再作为当前产品实现推进。

## 处理方式

不再推进。若未来重新引入对话建议，应以新的需求和规格重新立项，不复用本历史 Bug 的未完成处理流程。
