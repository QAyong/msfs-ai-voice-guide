# Bug：聊天面板展开后不跟随悬浮球

**日期：** 2026-07-20

**优先级：** 高

**状态：** 待修复

## 复现步骤

1. 将聊天面板收起为悬浮球。
2. 把悬浮球拖到另一侧屏幕边缘或新的垂直位置。
3. 点击悬浮球重新展开聊天面板。

## 实际结果

聊天面板恢复到上一次展开时保存的旧坐标，没有从悬浮球当前所在的屏幕边缘和垂直位置向内展开。现场状态中，悬浮球位于 `(8, 142)`，展开面板仍保存为 `(752, 142)`。

## 预期结果

悬浮球是聊天面板收起后的同一窗口状态。重新展开时应继承悬浮球当前显示器、停靠侧和垂直位置，只恢复聊天面板的宽高；不得恢复与悬浮球分离的旧 `x`、`y`。

## 影响范围

- 悬浮球跨屏幕、跨左右边缘或沿屏幕垂直方向移动后的再次展开。
- 窗口位置和尺寸持久化后的应用重启。
- 多个开发实例同时运行时，状态文件可能被不同进程交替覆盖，进一步放大位置混乱。

## 原因

`assistant:set-collapsed`（聊天面板收起状态切换）在展开时直接使用 `expandedAssistantBounds`（上次展开边界）的完整 `x`、`y`、`width`、`height`。悬浮球拖动只更新收起窗口位置，没有同步改写完整的展开边界，因此旧坐标覆盖了悬浮球的新位置。

## 修复方案

- 展开时以悬浮球当前边界和当前显示器为位置来源。
- `expandedAssistantBounds` 只提供上次展开宽高，新的 `x` 按当前停靠侧向屏幕内计算，新的 `y` 继承悬浮球并限制在工作区内。
- 增加“保存的展开坐标与悬浮球位置冲突”回归测试。
- 真实 Electron 验收前清理本项目残留的重复开发实例，确保只有一个主进程写窗口状态。
