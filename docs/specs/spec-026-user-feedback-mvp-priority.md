# Spec-026：用户反馈需求优先级

**状态：** 待审阅
**目标：** 在一周内优先完成最有复用价值、风险最低的用户反馈

## 当前进度

Spec-022“游戏内 POI 读取”已经完成，并已通过 Geo Cloud 真实坐标验证。它现在可以为用户主动询问和探索 Planner 提供标准化的 `gamePois` 数据。

## 建议排序

| 顺序 | 需求 | 优先级 | 建议 | 原因 |
| --- | --- | --- | --- | --- |
| 1 | [游戏内 POI 读取](spec-022-game-poi-reading.md) | P0 | 已完成 | 已复用 `getLocationContext`，完成 `game_poi` 标准化、探索复用和真实坐标验证。 |
| 2 | [自动导游模式](spec-023-auto-tour-mode.md) | P0 | 第二个完成 | 可以复用现有探索、地点上下文、TTS 和 LiveKit，只需增加自动触发、去重和暂停控制。 |
| 3 | [EFB 离线地名地图](spec-025-efb-offline-labeled-map.md) | P1 | 第三个完成 | 用户价值明确，但需要新增 EFB 应用、离线地图数据、安装开关和 MSFS 重启验证。 |
| 4 | [有限的 MSFS 飞机操作](spec-024-msfs-aircraft-actions.md) | P1 | 最后完成 | 会改变模拟器状态，需要确认、白名单、结果回读和多机型实测，风险最高。 |

## 一周执行建议

### 只能完成一个需求

“游戏内 POI 读取”已经完成。它提供的 `gamePois` 将作为自动导游的地点上下文基础。

### 可以完成两个需求

下一步可完成“自动导游模式”。它可以继续复用当前探索、`gamePois`、TTS 和 LiveKit 能力。

### EFB 地图的处理方式

如果本周必须交付 EFB 方向，建议先做一个技术 Spike：

1. EFB 应用能否读取飞机位置；
2. EFB 能否加载本地离线地图文件；
3. 安装包能否随主程序安装并在设置中开启。

三个验证都通过后，再进入完整地图和地名实现。不要先做全球详细 POI 数据。

### 飞机操作的处理方式

本周只建议完成协议和确认流程，不建议直接承诺“AI 自动驾驶”。如果要实机验证，先只支持自动驾驶开关和目标高度；当前实现已经完成受控实机验证，自动驾驶工具默认开启，但仍会在执行前检查机型能力并在执行后读取实际状态。

## 依赖关系

```text
游戏内 POI 读取 ──┐
                  ├─ 自动导游模式
现有探索/TTS ─────┘

EFB 离线地图：独立需求，可单独开发

飞机操作：独立需求，但需要更严格的安全和机型验证
```

## 当前建议结论

先实现 [Spec-023](spec-023-auto-tour-mode.md)。EFB 地图排在第三，飞机操作排在第四。

当前仍需确认的事项：

1. EFB 地图开关是否默认关闭，并在重启 MSFS 后生效；
2. 飞机操作第一版是否只支持自动驾驶开关和目标高度。
