# Spec-018：MSFS 运行时稳定性与桌面体验一致性

**创建日期：** 2026-08-08  
**状态：** 待实施  
**优先级：** P0（MSFS 运行时稳定性）、P1（诊断导出）、P2（设置与消息界面）

## 背景

当前版本已经可以在启动阶段显示 MSFS 已连接，但实际使用中存在两类影响核心功能的问题：

1. SimConnect 会话开始时正常，进行一次或多次对话后可能变为“游戏未连接”；此时 Agent 无法继续调用 MSFS 工具。
2. EFB 航路调用出现超时。该问题在最近一次改动后出现，暂不能确认是 CLI、daemon、Community Package、请求排队还是调用方生命周期造成。

此外，用户反馈了三个不阻断核心功能、但会影响使用体验和问题定位的问题：聊天气泡宽度和换行不理想、设置下拉框交互不统一、诊断导出包含过多无关日志。

本规格将这些问题分成一个有先后顺序的专项。MSFS 运行时修复完成前，不把前端细节优化视为发布阻断解除。

## 目标

- 对话过程中 SimConnect 与 MSFS CLI 保持可持续调用；发生短暂故障时能够识别、重试或恢复。
- EFB 请求拥有明确的超时、取消、错误分类和恢复行为，不因一次超时拖住后续请求。
- 诊断导出默认聚焦当前故障时间段和 MSFS 相关事件，仍然保留用户主动扩大范围的能力。
- 音色、语言、搜索三个下拉选择使用同一套组件和交互规则。
- 聊天气泡在不破坏可读性的前提下充分使用聊天面板宽度，并只在内容确实超出可用宽度时换行。

## 非目标

- 不增加 MSFS 写操作，不控制自动驾驶、航班加载、相机或 Input Event。
- 不把 SimConnect 连接迁移到 Renderer，也不让 Renderer 直接启动 CLI。
- 不在本专项中引入新的搜索 Provider、云端日志上传或远程故障收集。
- 不为了隐藏问题而把“检测失败”伪装成“游戏已连接”。

## 现有边界

- MSFS 运行时调用继续通过 `src/msfs/`（MSFS 适配层）和受控 CLI 进程完成。
- `MsfsCliClient`（CLI 客户端）继续作为请求并发、超时、重试和诊断的统一入口。
- `MsfsConnectionMonitor`（连接监控器）继续负责主进程标题栏的连接状态；外部 UI 仍只显示“游戏已连接/游戏未连接”，内部可以保留更细的诊断状态。
- EFB 航路仍依赖实际 `InstalledPackagesPath\Community2024\msfs-native-cli-route-bridge`，不能把应用资源目录当作游戏已加载的 Bridge。
- 诊断数据必须继续使用现有脱敏器，禁止写入 API Key、Token、JWT、Cookie、`.env` 原文和凭据 blob。

## 实施阶段

### 阶段 A：建立可定位的 MSFS 故障时间线（P0 前置）

在修复行为前，补齐以下结构化事件。每条事件至少包含 `timestamp`、`component`、`operation`、`requestId`（如果已有）、`durationMs`（如果已结束）和 `result`。

| 事件                   | 必须记录的内容                                                             |
| ---------------------- | -------------------------------------------------------------------------- |
| CLI 进程启动/结束      | 参数摘要、退出码、是否超时、输出是否可解析；不得记录完整凭据或原始认证参数 |
| MSFS 请求排队          | 入队时间、开始时间、等待时长、队列长度、操作名                             |
| SimConnect/daemon 探测 | `status`、`AircraftLoaded`、daemon 可用性、Bridge 可用性                   |
| EFB 请求               | `route get --source efb`、耗时、超时/重试次数、最终错误码                  |
| 连接状态变化           | 原状态、新状态、触发原因、最近一次成功请求时间                             |
| Agent 工具调用         | 工具名、成功/失败、错误码、耗时；不记录完整工具返回正文                    |

导出问题的第一版不要求马上重写所有诊断存储。先保证一次用户复现可以回答：哪一个请求开始失败、失败前是否发生过超时、daemon 是否仍在运行、连接状态何时变化、重试是否真的执行。

### 阶段 B：修复 SimConnect 会话稳定性（P0）

- 统一所有 MSFS 调用使用同一个有效的 `MsfsCliClient`，禁止连接监控、Agent 工具和探索流程各自创建互相不知情的客户端或 daemon 生命周期。
- 检查 Worker 重启、会话重连、窗口关闭和设置保存时，旧请求、旧定时器和旧客户端是否被取消；旧实例不得在新实例启动后继续写入连接状态。
- 连接监控遇到单次失败时必须发布真实的未连接/检测中结果，同时允许下一轮探测恢复；不得因为一次异常让监控永久停止，也不得因为一次旧结果覆盖新结果。
- 对临时性的 CLI 不可用和超时执行有限重试，并使用退避；协议错误、版本不匹配和 Community Package 缺失不得无条件重试。
- 连接状态的判断以有效的 CLI/SimConnect 结果为依据。只有状态探测或有效飞行数据请求成功时，才能恢复“游戏已连接”。
- 应用退出、MSFS 退出或 Worker 重启时，必须停止相关轮询和子进程，避免残留 daemon 或旧进程占用后续请求。

### 阶段 C：修复 EFB 超时与请求隔离（P0）

- 为 EFB 路由调用保留明确的 `ROUTE_TIMEOUT`、`ROUTE_BRIDGE_UNAVAILABLE`、`ROUTE_BRIDGE_VERSION_MISMATCH` 和 `ROUTE_NOT_FOUND` 分类。
- 一次 EFB 超时必须释放请求队列；后续的 `getFlightSnapshot`、`getNextWaypoint` 或再次 EFB 请求不能无限等待前一个请求。
- 对可重试错误最多进行有限次数重试；每次重试记录等待时长和结果，最终返回稳定的公开错误信息。
- 用户主动取消对话、切换设置、退出应用或 Agent 会话失效时，EFB 请求必须响应 `AbortSignal`（取消信号），不得在后台继续占用 CLI 通道。
- EFB 调用失败后，连接状态提示不得简单等同于 SimConnect 断开；界面应能通过诊断信息区分“游戏连接正常但 EFB Bridge 不可用”。

### 阶段 D：诊断导出聚焦故障上下文（P1）

默认导出范围调整为“当前故障窗口”，建议默认包含点击导出前后可配置的时间范围，初始值为最近 15 分钟，并优先保留：

- MSFS/SimConnect/daemon/Bridge 相关事件；
- CLI 请求、超时、重试、连接状态变化；
- 当前会话的必要工具调用摘要；
- 应用版本、CLI/Bridge 版本、运行环境和 readiness（就绪状态）摘要。

完整对话日志、完整搜索来源和全部历史日志改为可选项。导出界面至少提供：

- 时间范围：最近 15 分钟、最近 1 小时、自定义；
- 模块：MSFS、Agent/工具、会话、应用；
- 是否包含完整对话内容；
- 导出前显示预计包含的日志流和时间范围。

如果当前实现暂时不能按事件筛选，第一步至少将 MSFS 诊断单独输出为 `msfs.ndjson`，并在 `manifest.json` 中记录筛选条件；不得继续把全部日志无说明地打进默认 ZIP。

### 阶段 E：统一设置选择器（P2）

音色、语言、搜索统一使用音色选择器的交互模式：

- 统一触发器高度、边框、箭头、展开状态和选中状态；
- 点击触发器展开，点击选项后立即更新草稿值，点击外部区域关闭；
- 支持键盘上下移动、Enter 确认、Escape 关闭，并提供正确的 `aria-expanded`、`aria-selected`；
- 当前值在未展开时清晰显示；选项的主标题、辅助说明和禁用状态使用同一布局规则；
- 语言、搜索不再使用与音色不同的原生 `select`/自定义菜单混合表现，除非存在明确的无障碍或平台兼容原因并在文档中说明。

### 阶段 F：调整聊天气泡布局（P2）

- 助手消息气泡应占聊天面板的主要可用宽度，左右保留稳定内边距；用户消息可保持较窄的右对齐宽度。
- 普通中文、英文和连续英文文本在未达到容器最大宽度前不应产生异常换行；超长 URL、代码样式文本和单个不可断词仍必须可安全换行。
- 气泡宽度应随窗口和聊天面板变化响应式调整，不能依赖固定像素宽度。
- 调整后必须验证窄窗口、放大窗口、长中文句子、长英文句子、长 URL 和 Markdown 渲染结果。

## 验收标准

### P0：MSFS 运行时

- [ ] 应用先启动、MSFS 后启动：进入飞行场景后连接状态能恢复为已连接。
- [ ] MSFS 先启动、应用后启动：应用能检测到已连接，不需要重复启动多个 daemon。
- [ ] 连续完成至少 10 次包含 MSFS 工具的对话后，连接状态不无故降为未连接。
- [ ] 在一次 EFB 超时后，下一次 EFB 请求和普通飞行数据请求仍能在限定时间内执行。
- [ ] EFB 没有航路、Bridge 未安装、Bridge 版本不匹配、CLI 超时分别返回可区分的结果。
- [ ] 重启 Agent Worker、切换服务设置、关闭窗口和退出应用后，没有旧请求或旧定时器继续覆盖新连接状态。
- [ ] MSFS 真正退出或 SimConnect 不可用时，前端显示未连接；恢复后可以自动重新连接。

### P1：诊断

- [ ] 一次故障可以从导出内容中定位到失败操作、失败时间、耗时、错误码、重试过程和连接状态变化。
- [ ] 默认导出不再包含无关日期的全部历史日志，也不默认包含完整对话全文。
- [ ] 用户主动选择完整范围时仍能导出足够的对话和工具上下文。
- [ ] 导出的所有日志和元数据均经过统一脱敏，标准 ZIP 工具可以打开，取消或失败不留下残缺目标文件。

### P2：桌面体验

- [ ] 音色、语言、搜索下拉选择器的视觉样式、展开/收起、键盘操作和无障碍状态一致。
- [ ] 聊天气泡在常见窗口尺寸下使用足够的面板宽度，普通文本不会提前异常换行。
- [ ] 以上 UI 调整不改变会话消息内容、工具调用语义和设置保存/重连流程。
