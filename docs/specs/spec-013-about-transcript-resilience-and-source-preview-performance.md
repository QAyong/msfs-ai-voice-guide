# Spec-013：关于页、语音转写纠错与来源网页首屏加速

**日期：** 2026-07-28<br />
**状态：** 提议（STT 提示词容错和来源网页首屏加速已实现；关于页与高级转写韧性待实施）<br />
**前置决策：** [ADR-005](../adr/adr-005-deepseek-llm-baseline.md)、[ADR-010](../adr/adr-010-secure-desktop-settings-global-ptt-and-diagnostics.md)<br />
**关联规格：** [Spec-004](spec-004-web-frontend-and-source-preview.md)、[Spec-012](spec-012-desktop-settings-localization-global-ptt-and-diagnostics.md)

## 目标

在不扩大 Electron 安全边界、不让每次语音都多一次确认、也不以牺牲来源网页真实性换取速度的前提下，完成三项体验改进：

1. 设置中心增加“关于”页，提供版本、赞赏、教程和广告/合作链接；
2. 降低 STT 误识别被 LLM 当作确定事实理解的概率，并允许用户以低摩擦方式更正；
3. 让来源网页在出现可见首屏后立即显示，不再等待整页慢资源完成。

本规格只定义产品行为、边界和验收。不在本次实施中更换 STT 供应商、增加语音唤醒、持久保存原始录音、实现通用浏览器，或默认将对话上传云端。

## 1. 设置“关于”页

### 1.1 信息架构与交互

现有设置的左侧导航由“通用”“服务配置”扩为“通用”“服务配置”“关于”三个一级页面。进入“关于”时不创建草稿、不显示“保存”或“保存并重新连接”，也不触发 Agent 重连。

关于页按以下顺序显示：

| 区块       | 内容与行为                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------- |
| 软件信息   | 产品名、`app.getVersion()` 返回的软件版本；可额外显示构建号，但不能把 Electron、Node 或任何密钥当作产品版本。    |
| 赞赏       | 本地随包的赞赏二维码或同等本地图片；旁边显示渠道名称和简短自愿原则。二维码不从远程网页加载，也不包含可执行链接。 |
| 教程       | 一个或多个明确命名的 HTTPS 教程链接；点击后用系统默认浏览器打开。                                                |
| 广告与合作 | 一个或多个明确标为“推广/合作”的 HTTPS 链接；显示目的地域名，点击前不在应用内加载落地页。                         |

当前需求尚未提供赞赏渠道、二维码、教程地址或广告地址。实现前由产品提供真实内容；不得为了填满界面使用虚构的二维码、短链、广告商或示例 URL。链接缺失时该条目不渲染，不显示不可用的空按钮。

关于页的外链采用主进程维护的静态白名单清单。Renderer 只接收标题、可本地化说明、显示域名和安全的 `https:` URL；点击由受限 IPC 请求主进程再次验证 URL 后调用 `shell.openExternal()`。不提供可编辑 URL、内嵌网页、复制密钥或读取本地文件的能力。广告链接必须有可本地化的推广标识，不能伪装为教程或产品功能。

### 1.2 资源与版本契约

新增仅含公开内容的版本化 `AboutInfo` DTO，例如：

```ts
type AboutLink = {
  id: 'tutorial' | 'promotion';
  label: string;
  description?: string;
  url: string;
  hostname: string;
};

type AboutInfo = {
  schemaVersion: 1;
  productName: string;
  version: string;
  supportQrAsset?: string;
  supportChannelLabel?: string;
  links: readonly AboutLink[];
};
```

`version` 的唯一运行时来源是 Electron 主进程的 `app.getVersion()`，其发布值来自根目录 `package.json`。关于内容本身放在受版本控制的本地公开资源清单，赞赏图片放在随包的本地资源中；两者均不含用户偏好、服务配置、密钥、动态远程配置或统计标识。

Preload、全局 TypeScript 声明、主进程 IPC 和 Renderer 在边界处共享 Zod Schema。`about:get-info` 只授予可信设置 Utility Window；`about:open-link` 只接受清单中已存在的 `id`，不接受 Renderer 提交的任意 URL。

### 1.3 本地化与无障碍

“关于”、区块标题、赞赏的自愿说明、教程、推广标识和错误信息随现有 `zh-CN` / `en-US` 设置切换。版本号、渠道名、域名与 URL 不翻译。所有图标按钮和二维码都有本地化的可访问名称；二维码必须有等价的可见渠道文字，不能只靠图片传达赞赏对象。

## 2. STT 转写韧性

### 2.1 决策

不把 LLM 提示词当作唯一纠错手段，也不对每一段语音强制弹确认。采用以下四层链路：

```text
音频/服务配置
  -> 领域上下文与词表（供应商能力可用时）
  -> 原始转写 + 确定性歧义判定
  -> LLM 的上下文理解、工具核验和必要时的用户确认
```

用户的原始最终转写是审计和界面展示的事实来源，系统不得悄悄把它替换为猜测的机场、航点或地名。任何规范化结果必须带有“候选/已确认”的来源状态，并且只有在上下文证据充分时才作为给 LLM 的辅助上下文，而不是篡改用户原话。

### 当前实现状态（2026-07-28）

已完成第一阶段的提示词容错：`createGuideInstructions()` 现在明确告知导游，用户输入可能来自含同音字、错字、漏字或专有名词偏差的语音转写；导游应结合当前对话、已知事实和可用模拟器上下文自然理解用户意图，避免机械逐字解读，并且不解释内部判断过程。

该阶段不改变 STT 请求、音频回合提交或界面交互。领域词表、供应商置信度/候选解析、`TranscriptGuard` 和用户确认界面仍未实施。

### 2.2 领域词表与供应商能力

每个 Room 会话维护一个短生命周期的 `FlightSpeechContext`，内容只来自以下已存在的、可核验的数据：用户本轮文字显式输入、当前 EFB 航路及下一航点、当前机场/附近设施、已选择的搜索结果和产品固定词。词条包括 ICAO/IATA、航点、跑道、飞机/航空公司型号、地名的中英文常用说法与易混淆别名。

在接入前必须以当前选用的火山 STT 资源的官方文档和实际响应为准，确认其是否支持热词、上下文短语或自定义词表，以及字段、上限、费用和语言限制。若支持，则由 `src/providers/stt/volcengine.ts` 通过经过 Zod 校验的请求参数发送有长度和数量上限的会话词表；若该资源不支持，绝不能发送猜测的协议字段，仍保留后续三层策略。

词表只影响识别偏好，不可当作事实来源；每次位置、航路或设施更新时替换内存中的会话词表，断开 Room、关闭语音或切换 Agent 后清除。不得把词表、原始音频或全量对话作为新的云端持久化数据。

### 2.3 歧义识别、确认与 LLM 行为

STT 适配器继续区分 interim 和 final 结果，并保留供应商实际返回的置信度、词级时间与候选信息（若有）。当前实现将 `confidence` 固定为 `0`，因此实施前先扩展解析和测试；若供应商没有可靠置信度字段，判定器只使用可解释的规则，不能伪造数值置信度。

最终转写进入 LLM 前，`TranscriptGuard` 只产生三种结果：

| 结果      | 条件                                                                                   | 对话行为                                                                                 |
| --------- | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `pass`    | 普通问句，或词表/当前上下文可唯一匹配                                                  | 立即正常提交；LLM 仍可依据上下文理解口语、省略和同音字。                                 |
| `assist`  | 存在唯一且高相似度的领域候选，但原文不匹配                                             | 提交原文和带证据来源的候选提示；LLM 可自然复述确认，例如“你是想问 ZBAA 附近的天气吗？”。 |
| `confirm` | 多个候选接近、机场代码/数字/跑道/航点/目的地等关键实体无法唯一确定，或用户主动要求改正 | 不执行依赖该实体的工具调用；显示紧凑的可编辑转写与候选，用户可点选、编辑后发送或重说。   |

确认只针对会改变查询对象或可能导致错误解释的实体，不针对“你好”“继续讲”“今天天气”等普通自然对话。默认确认窗口应短且非阻断：用户可在约 1.5 秒内修改最终转写；若未被判为 `confirm`，超时后正常发送。`confirm` 状态不自动把其中一个候选发给 LLM，直到用户确认、改写或取消。

LLM 提示词补充以下约束：转写可能含同音字、错字或漏词；把 STT 文本当作用户意图的线索而非绝对事实。遇到地点、机场、航点、跑道、频率、数值或“这里/下一站”等不确定实体时，优先使用已有 MSFS 工具核验可用上下文；不能唯一推断时，先用一句简洁问题确认，不能凭发音相近擅自断言。此约束不得弱化现有“当前飞行数据只来自相应 MSFS 工具”的边界。

### 2.4 可观测性与隐私

诊断记录增加脱敏的转写质量事件：是否 final、是否有供应商置信度、`pass/assist/confirm` 结果、候选数量、用户是否编辑/重说、端到端延迟。诊断仍可包含已存在的用户转写和对话上下文，但不记录原始音频、未匹配的全局按键、完整词表、凭据或供应商认证字段。

质量指标以用户主动更正率、`confirm` 取消率、确认耗时、候选接受率和确认后工具参数错误率衡量。不要以“自动改写次数”作为成功指标；成功是减少误解而非增加系统猜测。

## 3. 来源网页首屏加速

### 3.1 当前瓶颈

目前 `showRemoteSource()` 每次选源都会新建 `WebContentsView`，并且在 `did-finish-load` 后才 `addChildView()`。许多新闻、百科和商业站点会等待广告、统计、图片或第三方脚本完成，因此用户即使主文档已经可见，仍只能看到本地加载页。当前持久 session 能复用 HTTP 缓存，但不能消除每次新建远程渲染进程和“等整页完成再展示”的等待。

### 3.2 决策与状态机

来源窗口创建并完成本地 Renderer 加载后，主进程预热一个安全配置完全相同的远程 `WebContentsView`，仅加载 `about:blank`。预热不发起第三方网络请求、不预取搜索来源、不写入来源历史；关闭来源窗口、返回预览后超过空闲上限或切换到新的来源集合时销毁该视图。

用户选择来源时复用预热视图（不存在时按现有方式创建），先发布 `loading` 状态并开始导航。主文档获得可见首屏后立即附着视图并发布 `ready`；`did-finish-load` 只作为后台完成信号，不是“可以让用户看到网页”的门槛。实现优先使用该导航的 `dom-ready` 或经验证等价的首屏可见事件，且必须在当前 Electron 版本与典型目标站点上验证事件语义。

```text
搜索结果预览
  -> 预热安全空白视图
  -> 选择来源 / 开始导航
  -> 首屏可见（附着并展示原网页）
  -> 后台加载完成
```

首次可见前仍保留当前加载页面和 15 秒首屏超时。首屏可见后清除该超时，不应因广告或分析资源继续缓慢而把已经可用的网页覆盖成错误页。顶层文档后续导航、HTTP 4xx/5xx、重定向到不安全协议、主框架网络失败和渲染进程退出仍按现有安全/错误状态处理；子资源失败不影响可读的主文档。

不保留上一来源的可交互页面作为下一来源的预览，也不执行对第三方 URL 的投机预加载。这样既避免误导用户，也避免在未选择链接前向站点暴露访问行为。现有 `persist:source-preview` 分区继续只用于正常缓存；不得通过放宽沙箱、权限策略或导航白名单来追求速度。

### 3.3 性能预算与降级

在同一网络条件、同一来源集合中，记录但不外传以下时间点：点击来源、`loadURL` 开始、首屏可见、`did-finish-load`、失败。首要指标是点击到首屏可见（TTFV），整页完成只作诊断指标。

目标为：热预览视图下，本地页面切换到导航开始不额外增加超过 100 ms；常见可访问网页的中位 TTFV 相比当前实现明显下降，验收时至少以本机基准证明不再受 `did-finish-load` 阻塞。慢站、离线和实际服务器响应慢不能承诺固定秒数，应继续提供重试和系统浏览器打开。

资源紧张、WebContentsView 预热失败或 source window 关闭过程中出现竞态时，安全降级到当前“按需创建、加载后显示”路径；不得出现空白覆盖层、已销毁视图回调改变新页面状态、或任一远程页面获得 Preload/Node/IPC 权限。

### 3.4 当前实现状态（2026-07-28）

来源窗口在本地 Renderer 就绪后，会后台预热一个同样开启沙箱、上下文隔离且禁用 Node 的 `about:blank` `WebContentsView`。选择来源时复用该视图；首个 `dom-ready` 事件即附着视图并进入 `ready` 状态，`did-finish-load` 仅作为兼容回退，不再阻塞首屏展示。

15 秒计时器现只约束首屏显示。首屏已出现后会清除计时器，缓慢的广告、图片或统计资源不会覆盖已经可阅读的网页。来源加载失败、返回结果列表和窗口关闭后都会销毁旧远程内容，并重新后台预热空白视图；原有缩放、窗口拉伸、权限拒绝、导航校验和系统浏览器打开行为保持不变。

在 2026-07-28 的同机同网 Electron 基准测试中，`example.com` 的首屏/整页时间为 `0.904` / `0.917` 秒，Bing 搜索页为 `1.639` / `1.649` 秒；两者本身没有明显慢尾资源。MSN 中文首页的首屏为 `2.269` 秒、整页完成为 `10.507` 秒，说明旧逻辑会额外阻塞约 `8.238` 秒，而当前实现可在首屏出现后继续后台加载。

关于页和 STT 的领域词表、置信度/候选解析、`TranscriptGuard` 与确认界面仍处于提议状态；本次已经落地的是 STT 第一阶段提示词容错与来源网页首屏加速。

## 4. 实施范围与测试

### 4.1 预计改动边界

| 主题                   | 主要模块                                                                          |
| ---------------------- | --------------------------------------------------------------------------------- |
| 关于 DTO、链接白名单   | `shared/`、`desktop/main/`、`desktop/preload/`、`desktop/renderer/`、本地公开资源 |
| 设置导航和关于 UI      | `desktop/renderer/src/main.tsx`、`desktop/renderer/src/style.css`                 |
| STT 上下文、解析与守卫 | `src/providers/stt/`、`src/conversation/`，以及经核验的 LiveKit 会话输入边界      |
| 来源预热与首屏状态     | `desktop/main/index.ts`、`shared/source-preview.ts`（仅在状态契约确有需要时）     |
| 诊断与测试             | `desktop/main/diagnostics.ts`、`tests/unit/`、必要的 Windows 手工冒烟             |

Provider 创建仍只经 `src/providers/registry.ts`；Agent 入口不直接实现火山协议。远程网页仍为 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`，且默认拒绝权限和新窗口。

### 4.2 自动化验收

- [ ] 设置导航包含“关于”，切换到该页不会保存偏好、重连 Agent 或暴露服务凭据。
- [ ] `about:get-info` 仅对可信设置窗口返回公开 DTO；版本取自主进程，未配置链接和二维码时不生成虚假入口。
- [ ] `about:open-link` 拒绝未知 `id`、非 HTTPS 和不在白名单中的 URL；有效教程和推广链接交给系统浏览器，推广在 UI 中有本地化标识。
- [ ] STT 解析保留供应商实际提供的置信度/候选元数据；无该字段时明确为空，不再伪造为可靠数值。
- [ ] 词表构建只包含允许的数据源，遵守数量/长度上限，并在会话结束后清除；供应商不支持词表时不发送未定义协议字段。
- [ ] `TranscriptGuard` 对唯一匹配、近似唯一和多候选分别产生 `pass`、`assist`、`confirm`；`confirm` 不触发依赖未确认实体的工具调用。
- [x] 现有提示词测试覆盖“转写可错、自然理解且不解释内部判断过程”的约束，并继续覆盖 MSFS 数据来源边界。
- [ ] 选择来源时复用预热视图；首屏可见事件会在 `did-finish-load` 前附着视图，且成功首屏后慢子资源不会触发 15 秒失败页。
- [ ] 非安全跳转、顶层网络失败、HTTP 错误、渲染进程退出、超时、返回来源列表和窗口关闭均不会遗留视图、计时器或过期回调。

### 4.3 人工验收

- [ ] 在简体中文和 English 下检查关于页排版、键盘焦点、二维码等价文字和外链打开行为。
- [ ] 用真实飞行术语、相近地名、机场代码、跑道和航点进行 PTT 与连续对话测试；普通对话不应被反复打断，歧义项应可快速修正。
- [ ] 在 MSFS 前台下验证全局按住说话既有消费行为未改变，且转写确认不会让录音悬挂。
- [ ] 在冷缓存/热缓存、快速站点/慢第三方资源站点和网络失败场景下记录 TTFV，确认网页首屏出现早于整页完成且原有安全边界没有回归。

## 5. 实施前待确认项

1. 产品提供实际的赞赏渠道、二维码资产、教程链接和推广/广告链接，并确认每个推广链接的展示文案和地区合规要求。
