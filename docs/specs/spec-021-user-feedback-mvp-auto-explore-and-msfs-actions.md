# Spec-021 草案：自动探索导游与有限 MSFS 操作

> 本文是拆分前的合并草案。当前请以 [Spec-026 用户反馈需求优先级](spec-026-user-feedback-mvp-priority.md) 作为排序依据，并分别审阅 [Spec-022 游戏内 POI 读取](spec-022-game-poi-reading.md)、[Spec-023 自动导游模式](spec-023-auto-tour-mode.md)、[Spec-024 有限飞机操作](spec-024-msfs-aircraft-actions.md) 和 [Spec-025 EFB 离线地名地图](spec-025-efb-offline-labeled-map.md)。

**状态：** 草案，待审阅
**目标周期：** 一周内完成第一版 MVP
**说明：** 本文只整理用户反馈和最小实现范围，未确认的内容保留为待决策项。

## 1. 用户反馈

1. 游戏助手目前不能很好地读取游戏内 POI（兴趣点），用户希望知道附近有什么地标。
2. 游戏助手目前主要提供读取能力，用户希望 AI 能执行部分飞机操作，例如设置自动驾驶。
3. 用户希望有“全自动导游”开关，不需要持续语音输入，助手可以自动介绍沿途的人文和景观故事。

### 拆分说明

本文最初没有包含 EFB 地图需求。该需求现在已经纳入当前项目，但作为独立的 EFB 应用处理，具体范围请以 [Spec-025](spec-025-efb-offline-labeled-map.md) 为准；本文其余内容仅作为拆分前的合并记录。

## 2. 当前项目基础

- `getLocationContext` 已有当前位置、城市、自然地貌和游戏 POI 的上下文入口。
- 探索模式已经能够读取 MSFS 上下文，调用百科/视频来源，生成主题和简短 `introduction`。
- 探索模式当前由用户主动触发；本需求计划在其上增加自动触发和语音播报。
- Native MSFS CLI 已有 `simvar set`、`key-event send` 和 `input set` 等写入能力，但 Agent 当前没有把这些写操作注册为高层工具。

相关代码：

- `src/msfs/guide-service.ts`：当前位置上下文。
- `src/msfs/explore-context.ts`：探索使用的飞行上下文。
- `src/explore/service.ts`：探索内容编排。
- `desktop/main/explore-controller.ts`：探索请求、缓存和位置变化判断。
- `shared/explore-contracts.ts`：探索结果和 `introduction` 字段。

## 3. 第一版需求范围

### 3.1 游戏内 POI 读取

用户可以询问：

- “附近有什么游戏内 POI？”
- “这附近有什么地标或自然景观？”
- “我刚才飞过了什么 POI？”

第一版返回：

- 附近有限数量的游戏 POI、自然景观或地标；
- 每个结果的名称、距离和数据来源（如果有）。

第一版先使用“游戏实时坐标 + Geo Cloud 中的游戏 POI 数据”。这用于回答助手的 POI 和探索问题，不等同于读取或修改 EFB 地图上的地名显示，也不承诺直接读取 MSFS 内部所有 Landmark POI。

### 3.2 基于探索的自动导游

自动导游不是新的内容系统，而是现有探索模式的自动触发方式。

用户打开“自动导游”开关后：

1. 系统确认 MSFS 已连接并能读取当前位置。
2. 后台定期获取当前位置和地点上下文。
3. 进入新的城市、地区、自然景观或 POI 后，调用现有探索流程。
4. 使用探索结果中的简短 `introduction` 进行语音播报。
5. 相同地点不重复播报。
6. 用户可以暂停自动导游，也可以停止当前播报。

第一版的自动播报：

- 只播报一段简短介绍；
- 不自动打开完整探索来源窗口；
- 不自动连续播放多个视频；
- 仍然复用现有百科、视频和网页来源配置；
- 仍然使用当前 LiveKit 会话和 TTS 管线。

### 3.3 有限的飞机操作

为了控制一周内的范围，第一版只考虑少量、明确的自动驾驶操作：

- 打开/关闭自动驾驶；
- 设置目标高度；
- 是否支持设置目标航向，待确认。

操作规则：

- 每次操作前，AI 必须向用户复述目标并获得明确确认；
- 操作只作用于当前用户飞机；
- 操作完成后读取状态并反馈成功或失败；
- 未确认、模拟器未就绪或参数无效时，不执行写操作。

## 4. 一周 MVP 建议优先级

### P0：必须完成

- 能返回附近有限数量的 POI/自然景观；
- 自动导游开关；
- 自动触发一次探索；
- 播报探索结果中的简短介绍；
- 去重、暂停和停止播报。

### P1：有时间再完成

- 自动驾驶开关；
- 设置目标高度；
- 操作确认和执行结果提示。

如果一周内只能完成一个完整方向，优先完成 P0。P1 应保持为受控实验能力，不影响普通只读导游。

## 5. 暂不包含

- 直接解析 MSFS 所有官方 Landmark POI 或场景包；
- 修改 EFB 地图的地名或地图显示；
- 自动起飞、自动降落和全自动航线飞行；
- 油门、襟翼、方向舵、姿态等高频闭环控制；
- 自动修改 EFB 航路或加载航班；
- 自动打开大量网页或视频；
- 新增独立的 POI、百科或新闻 Provider；
- 完整的自动导游路线规划和跨会话历史记忆。

## 6. 初步验收标准

### 地点和 POI

- 用户询问附近 POI 或景观时，助手能返回有限数量的 POI/自然景观，并说明来源。
- MSFS 未连接或 Geo Cloud 不可用时，不编造地点和 POI。

### 自动导游

- 开关关闭时，不自动触发探索或语音播报。
- 开关打开后，进入新地点时最多触发一次介绍。
- 同一地点不会反复播报。
- 用户可以暂停自动导游和停止当前播报。
- 自动介绍使用当前语言和 TTS 音色。
- 探索失败时不影响正常聊天和手动探索。

### 飞机操作

- 未经用户明确确认，不执行任何写操作。
- 自动驾驶操作失败时返回明确原因，不声称成功。
- 操作后能够读取并展示对应状态。
- 现有只读工具、语音会话和 MSFS 连接状态不受影响。

## 7. 待确认问题

1. 第一版的 POI 是否接受“游戏实时坐标 + Geo Cloud 游戏 POI 数据”，而不是直接读取 MSFS 内部 Landmark POI？
2. 自动导游的触发方式采用什么默认值？建议先沿用现有约 10 公里的位置变化阈值；是否还需要增加固定时间间隔？
3. 自动播报是否只需要一段约 20～40 秒的 `introduction`，完整主题和来源仍由用户手动打开探索查看？
4. 第一周是否确认只支持“打开/关闭自动驾驶 + 设置目标高度”？目标航向是否放到下一版？
5. 是否同意把“游戏 POI + 自动导游”作为 P0，把飞机操作作为 P1？
