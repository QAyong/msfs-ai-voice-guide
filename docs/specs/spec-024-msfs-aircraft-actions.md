# Spec-024：有限的 MSFS 飞机操作

**状态：** 待实现，安全实验功能
**建议优先级：** P1，本周最后处理
**目标周期：** 先完成受控验证，不承诺一周内覆盖所有飞机

## 目标

用户明确要求后，AI 可以执行少量、可验证的飞机操作，例如打开或关闭自动驾驶、设置自动驾驶目标高度。

## 第一版范围

只支持：

- 打开/关闭自动驾驶；
- 设置自动驾驶目标高度。

目标航向暂不纳入第一版，放到后续版本。

## 操作流程

```text
用户提出操作
  → AI 复述目标
  → 用户明确确认
  → 调用受控 MSFS 写操作
  → 读取结果
  → 告知成功或失败
```

用户没有明确确认时，不执行任何写操作。

## 当前基础

- Native CLI 已有 `simvar set`、`key-event send` 和 `input set`。
- 写操作当前要求显式 `--unsafe`。
- 当前 Agent 工具主要是只读工具，还没有面向用户的高层飞机操作工具。

相关代码：

- `native/msfs-cli/src/daemon/main.cpp`
- `native/msfs-cli/docs/cli-reference.md`
- `src/tools/msfs-guide.ts`

## 安全规则

- 新增独立的“允许飞机操作”设置，建议默认关闭；
- 只允许白名单操作，不能让模型直接提交任意 SimVar 名称；
- 每次写入前必须取得用户明确确认；
- 写入后必须重新读取状态；
- MSFS 未连接、变量不可写或机型不支持时，不执行并返回原因；
- 不做高频姿态、油门或方向舵闭环控制；
- 不做自动起飞、自动降落或全自动飞行。

## 验收标准

- 未确认时，任何操作都不会改变模拟器状态。
- 确认后，自动驾驶开关和目标高度在支持的机型上可以执行。
- 操作失败时返回明确错误，不声称成功。
- 操作后能读取并展示实际状态。
- 只读工具、语音会话和 MSFS 连接监控不受影响。
- 至少使用两类不同机型完成实机验证；无法支持的机型要明确提示。

## 为什么最后做

这是四项需求中风险最高的一项：它会改变模拟器状态，且不同机型对自动驾驶事件和变量的支持不完全一致。Native CLI 已经具备底层能力，但还需要新增确认流程、白名单、高层工具和真实机型验收。
