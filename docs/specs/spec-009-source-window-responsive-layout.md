# Spec-009：来源浏览窗响应式网页布局与临时自由移动

**日期：** 2026-07-25

**状态：** 已完成，运行时验收已确认

## 1. 背景

当前来源浏览窗提供“电脑布局”和“竖版布局”切换。竖版布局以固定的 768 CSS 像素作为排版宽度，电脑布局以固定的 1280 CSS 像素作为排版宽度，再将页面整体缩放进来源窗口。

这种固定虚拟宽度加整体缩放的方式不能自然反映来源窗口的真实尺寸。部分外部网页虽然发生了字体或页面缩放，但横向内容仍可能被裁切，拉伸窗口时也不能像普通浏览器一样根据真实可用宽度完成响应式重排。

本需求的目标不是模拟手机、平板或特定设备，而是让来源浏览窗成为一个可自由调整大小、按真实内容区域排版的普通桌面浏览器窗口；同时允许用户在本次打开期间把来源窗移动到自己需要的位置。

## 2. 决策

取消来源网页的“电脑布局”和“竖版布局”切换，不再使用固定的 768/1280 CSS 像素虚拟排版宽度。

来源网页统一使用浏览器式响应布局：

- 来源窗口默认尺寸保持约 440×600px，提供清晰、紧凑的默认竖版阅读区域。
- 来源窗口四边和四角均可拉伸，不锁定固定分辨率或宽高比。
- `WebContentsView` 的内容区域始终匹配来源窗口标题栏下方的真实可用区域。
- 网页视口宽高随来源窗口拉伸实时变化，由网页自身的 CSS 响应式规则重新排版。
- 网页默认保持 100% 缩放，不再为了塞入固定虚拟画布而自动整体缩小。
- 不显示手机、平板或电脑布局图标，也不维护对应的布局模式状态。
- 保留桌面 Chromium User-Agent、鼠标点击、鼠标滚轮、键盘输入、文本选择和原生网页交互。
- 不伪造手机 User-Agent，不模拟触摸屏、设备像素比或特定移动设备。

该决策取代 Spec-004 第 4.3、4.4 节中关于布局切换器、固定 768px 竖版布局和固定 1280px 电脑布局的要求。Spec-004 中关于远程网页隔离、来源状态机、安全导航、返回搜索结果、系统浏览器打开和关闭窗口的要求继续有效。

## 3. 用户体验

来源网页的布局由来源窗口的真实大小决定：

```text
用户拖动来源窗口边框
        ↓
网页内容区域同步改变
        ↓
网页获得新的真实视口宽高
        ↓
网页根据自身响应式规则重新排版
```

例如，在默认约 440px 宽的来源窗口中，支持响应式设计的网站通常会进入窄屏单栏布局。相比将 768px 页面整体缩入 440px 窗口，正文能够以接近网站原始字号显示，通常更大、更清晰，也更不容易发生横向内容缺失。

用户需要查看更多桌面内容时，可以直接拉宽来源窗口；需要减少遮挡时，可以将窗口拉窄。用户不需要理解或选择手机、平板、电脑、虚拟分辨率和缩放模式。

## 4. 外部网页兼容边界

应用负责向网页提供准确的真实视口尺寸，但不能保证第三方网站本身具备响应式设计。

- 支持响应式设计的网站应随窗口宽度自然切换单栏、多栏、导航和内容间距。
- 仅依靠手机 User-Agent 提供移动版的网站可能继续显示桌面页面，这是保留桌面浏览器身份的预期结果。
- 写死最小宽度或不支持窄屏的网站可以保留原生横向滚动。
- 对于无法在窄窗口内良好阅读的网站，用户仍可拉宽来源窗或使用“在系统浏览器打开”。
- 应用不得通过注入 CSS、改写网页 DOM 或强制缩小整个页面来掩盖第三方网站的布局问题。

## 5. 状态连续性与安全边界

- 调整来源窗口大小时不得重新加载网页或重建 `WebContentsView`。
- 当前 URL、登录会话、表单输入、媒体播放状态和滚动位置应自然保留。
- 本需求不改变远程网页的沙箱、权限、导航白名单和 IPC 隔离要求。
- 本需求不改变搜索结果列表；真实响应式网页视口仅应用于打开的外部原网页。

## 6. 窗口跟随与临时自由移动

来源浏览窗采用“默认跟随、手动移动后临时解除跟随”的交互：

- 每次新建并打开来源浏览窗时，仍按 Spec-004 的伴随定位规则出现在聊天面板内侧，并默认跟随聊天面板移动、拉伸和跨显示器。
- 用户通过来源窗标题栏主动拖动窗口后，来源窗在本次打开期间进入自由移动状态，停留在用户放置的位置。
- 进入自由移动状态后，聊天面板继续移动、拉伸或跨显示器时，不再自动改变来源窗的位置。
- 来源窗不提供“重新跟随”、锁定、吸附或模式切换按钮；用户无需理解额外的跟随状态。
- 关闭来源窗会清除本次自由移动状态。下次从聊天面板重新打开来源窗时，重新按聊天面板的当前位置计算伴随坐标并恢复默认跟随。
- 自由移动状态和来源窗坐标不跨关闭操作持久化；现有来源窗尺寸恢复规则保持不变。
- 无论来源窗当前处于默认跟随还是自由移动状态，收起聊天面板时都继续同步关闭来源窗，避免来源内容单独遮挡游戏。

该决策取代 Spec-004 第 3.3 节中“用户独立移动浏览窗后自动恢复到聊天面板旁”的要求。Spec-004 中关于初次伴随定位、避免跨屏闪跳、窗口安全区域、拉伸以及聊天面板收起时关闭来源窗的其他要求继续有效。

## 7. 验收标准

- [x] 来源网页标题栏不再显示电脑、手机、平板或竖版布局切换器。
- [x] 来源网页不再使用固定 768px 或 1280px 虚拟排版宽度。
- [x] 默认来源窗口约为 440×600px，并继续支持四边和四角拉伸。
- [x] 网页视口匹配标题栏下方的真实内容区域，默认缩放为 100%。
- [x] 拉伸来源窗口时，响应式测试网页能够根据真实宽度实时切换布局。
- [x] 拉伸过程中网页不重载、`WebContentsView` 不重建，并保留 URL、滚动位置和页面状态。
- [x] 鼠标、滚轮、键盘、文本选择等桌面网页操作保持可用。
- [x] 不修改 User-Agent，不启用触控或设备模拟。
- [x] 不支持响应式设计的网页可以横向滚动，并可通过系统浏览器打开。
- [x] 现有来源加载、错误恢复、导航安全和远程内容隔离测试继续通过。
- [x] 来源窗首次打开时位于聊天面板旁，并在用户尚未主动移动时继续跟随聊天面板。
- [x] 用户拖动来源窗后，本次打开期间来源窗保持在用户放置的位置，聊天面板移动、拉伸或跨屏不再将其拉回。
- [x] 来源窗不新增“重新跟随”按钮；关闭后重新打开即可恢复默认伴随位置和跟随行为。
- [x] 来源窗的自由移动状态和坐标不跨关闭操作保留，但已保存的有效窗口尺寸继续恢复。
- [x] 聊天面板收起时，无论来源窗是否已经自由移动，都同步关闭来源窗。
