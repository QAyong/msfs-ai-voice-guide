# Spec-023：自动导游模式

**状态：** 待实现
**建议优先级：** P0，第二个完成
**目标周期：** 一周内完成最小版本

## 目标

用户打开“自动导游”开关后，不需要持续语音输入；助手在飞到新的城市、地区、自然景观或游戏内 POI 附近时，自动播报一段简短介绍。

## 第一版行为

1. 用户在设置中打开“自动导游”。
2. 应用确认 MSFS 已连接并能读取当前位置。
3. 后台按现有 MSFS 读取能力检查位置和地点上下文。
4. 进入新地点或距离上次播报位置达到阈值后，触发现有探索流程。
5. 使用探索结果中的简短 `introduction` 进行 TTS 播报。
6. 同一地点不重复播报。

建议第一版沿用现有探索约 10 公里的位置变化阈值，并增加地点名称/POI 变化判断。

## 用户控制

- 自动导游开关：关闭后不再自动触发；
- 暂停自动导游：暂时停止自动触发，但不必删除设置；
- 停止当前播报：立即停止正在播放的介绍。

建议默认关闭，避免用户第一次启动应用时突然播报。

## 复用现有能力

- 复用 `src/explore/service.ts`；
- 复用现有探索结果中的 `introduction`；
- 复用现有 TTS 和 LiveKit 音频管线；
- 复用现有 `getLocationContext` 和 `getFlightSnapshot`；
- 不新增专用 POI Provider 或内容 Provider。

## 不包含

- 自动打开百科、视频或来源窗口；
- 连续播放多个故事；
- 自动规划完整导游路线；
- 自动控制飞机；
- 自动执行语音输入；
- 跨会话记忆已经播报过的地点。

## 验收标准

- 开关关闭时，不发生自动探索和自动播报。
- 开关打开后，进入新地点时最多触发一次介绍。
- 相同地点不会重复播报。
- 用户可以暂停自动导游并停止当前播报。
- 探索或 TTS 失败时，不影响手动聊天和手动探索。
- 自动介绍使用当前语言和当前 TTS 音色。
- 单段介绍建议控制在约 20～40 秒内。

## 依赖

- 依赖 [Spec-022 游戏内 POI 读取](spec-022-game-poi-reading.md) 提供更稳定的地点/POI 上下文；
- 依赖现有 [Spec-015 用户主动探索模式](spec-015-user-triggered-explore-mode.md)。
