# Spec-004：桌面悬浮语音面板与来源浏览窗

**日期：** 2026-07-17

**最后更新：** 2026-07-20

**状态：** Electron 桌面、LiveKit Room、单一来源入口、搜索结果预览和网页加载恢复已实现

## 1. 背景

用户在《微软模拟飞行》中需要与 AI 导游持续语音对话，同时必须保留驾驶舱、地景和仪表的主要可视区域。普通聊天应用和直播间式界面占用面积过大，因此本功能采用可收起的悬浮语音面板。

当 AI 回答包含网页来源时，用户还需要快速判断来源是否值得阅读。来源内容不能挤入聊天窗口，也不能变成产品自行改写的百科卡片。因此使用独立的伴随来源浏览窗，显示源网页或搜索结果预览。

本规格不改变现有 LiveKit 语音 Agent、`searchWeb`（公开网页搜索工具）及其来源质量策略。

## 2. 需求边界

**包含：**

- 64×72px 收起窗口，包含独立原生拖动把手和 48px 头像点击区，并吸附到最近显示器的左侧或右侧边缘。
- 可移动、可收起、可从四边和四角拉伸的紧凑语音聊天面板。
- Discord/微信式轻量气泡，只保留最近对话、来源入口和按住说话操作。
- 基于 LiveKit `LocalAudioTrack` 的按住说话，以及来自同一音轨的实时音量反馈。
- AI 回答下方只显示一个紧凑的“已检索 N 个网页来源”入口，不在聊天面板堆放多张来源卡片。
- 点击来源入口后，在独立伴随浏览窗中先显示本次搜索结果预览；选择某条结果后再加载原网页。
- 伴随浏览窗只提供“源网页”和“搜索结果预览”两类内容状态。
- 原网页加载提供加载中、成功、超时和失败状态，以及返回结果、重试、系统浏览器打开和关闭操作。
- 聊天面板与伴随浏览窗均限制在屏幕安全区域内。
- Windows 桌面壳及 `.exe` 打包架构建议。

**不包含：**

- 直播间式布局、弹幕、礼物、观众列表或持续占屏的角色立绘。
- 产品自建百科摘要、事实卡片、知识图谱或额外编辑内容。
- 多标签通用浏览器、收藏夹、下载管理、密码管理或浏览器扩展。
- Microsoft Flight Simulator 遥测、位置、航向、机场和航线数据。
- 正式 `.exe` 安装包、自动更新和代码签名。

## 3. 已确认的界面状态

| 状态           | 默认尺寸                       | 内容                                         | 行为                                                         |
| -------------- | ------------------------------ | -------------------------------------------- | ------------------------------------------------------------ |
| 头像悬浮球     | 收起窗口 64×72px；头像 48×48px | 导游头像                                     | 顶部把手拖动；头像点击展开；松开后吸附最近显示器的左/右边缘  |
| 语音聊天面板   | 默认 320×360px；最小 240×158px | 标题栏、最近对话、单一来源入口、按住说话按钮 | 标题栏拖动；四边和四角拉伸；“收起”恢复头像悬浮球             |
| 伴随来源浏览窗 | 默认 440×600px；最小 280×240px | 搜索结果预览或 HTTP(S) 源网页                | 始终出现在聊天面板内侧并跟随移动；可拉伸；关闭后保留聊天面板 |

### 3.1 头像悬浮球

- 收起后顶部显示 36×14px 可见拖动把手，下方显示 48px 头像，不显示额外文字按钮。
- 拖动把手使用 Electron 原生 `app-region: drag`；头像使用 `app-region: no-drag`，整个圆形区域点击后展开聊天面板。
- 拖动结束时保留垂直位置，只吸附到最近的左侧或右侧屏幕边缘。
- 显示器选择使用光标所在显示器或窗口覆盖显示器，必须正确处理负坐标、不同缩放比例和扩展屏排列。
- 点击展开时必须根据所在边缘向屏幕内侧展开，不能让面板主体出现在屏幕外。
- 展开、拖动和吸附使用同一位置状态；重新展开时继承悬浮球当前显示器、停靠侧和垂直位置，只恢复上次有效的聊天面板宽高，不能使用旧展开坐标覆盖悬浮球位置。

### 3.2 语音聊天面板

- 标题栏仅保留头像、名称、在线/聆听状态和“收起”。
- 对话区使用轻量气泡；导游回复内容中不重复显示头像。
- 默认只保留当前一问一答，内容超过高度后在对话区内部滚动。
- “按住说话”使用固定 160×38px 紧凑胶囊，是唯一持续突出显示的主操作，不占满底栏宽度。
- 首次按住时申请麦克风权限并创建 LiveKit `LocalAudioTrack`；后续按住复用并恢复该轨道，松开后立即静音。
- 请求权限时显示“正在连接”，聆听时原位切换为蓝色“松开结束”状态，并显示 5 根随输入音量变化的柱条；错误时显示可重试的“麦克风不可用”。
- 不显示放大、还原等传统窗口按钮；用户直接拖动边框调整大小。

### 3.3 伴随来源浏览窗

- 与聊天面板是两个独立视觉窗口，来源内容不会扩张聊天面板本身。
- 初次打开时优先放在聊天面板靠屏幕中心的一侧；空间不足时切换到另一侧，并始终保留 16px 安全边距。
- 浏览窗始终跟随聊天面板移动、拉伸及跨显示器后的新位置。
- 创建浏览窗时必须在构造参数中指定初始伴随坐标，并延迟到内容就绪后再显示，避免窗口先出现在主屏默认位置再跳到聊天面板旁造成闪跳。
- 用户尝试独立移动浏览窗时，主进程在移动结束后恢复到聊天面板旁的伴随位置，避免两个窗口分离。
- 四边和四角均为不可见拉伸热区，不显示右下角拉伸手柄。
- 收起聊天面板时同步关闭来源浏览窗，避免遗留大面积窗口遮挡游戏。

## 4. AI 回答与来源预览

### 4.1 聊天中的单一来源入口

一次成功的 `searchWeb`（公开网页搜索工具）调用与对应 Agent 回答关联后，在该回答下方只显示一个胶囊形入口：

```text
[ ◉ 已检索 10 个网页来源  › ]
```

- `N` 等于本次清洗、去重后实际可展示的来源数量，不使用供应商原始总召回数。
- 整个入口可通过鼠标、触摸和键盘激活，并具有可见焦点。
- 聊天面板不直接堆放单条来源卡片，也不重复渲染模型正文中的“资料来源”名称列表。
- 来源入口只能由结构化工具事件生成，不能扫描或猜测模型正文中的网站名称。
- 同一回答只显示一个入口；重复事件按搜索调用或请求追踪标识去重。
- 搜索失败、无结果或没有任何可展示来源时，不显示伪造入口；回答必须明确说明“本次未获取到可验证来源”。

### 4.2 搜索结果预览

点击来源入口后，伴随窗首先显示本次搜索结果列表，而不是立即打开第一条网页。窗口标题显示查询词和实际来源数量；普通用户界面不显示供应商 `RequestId`（请求追踪号）。

每条结果按搜索服务的标准化排序展示：

| 界面字段 | 内容与降级规则                                                       |
| -------- | -------------------------------------------------------------------- |
| 网站身份 | 网站图标和网站名称；图标失败时保留文字名称，名称缺失时显示 URL 域名  |
| 发布时间 | 有有效发布时间时显示；未知时省略，不推断日期                         |
| 标题     | 搜索结果标题；最多两行，超出截断                                     |
| 摘要     | 搜索服务返回的 `Snippet`（搜索摘要）文本；最多两至三行，不由 AI 改写 |
| 缩略图   | 使用搜索结果首张可用图片；不可用或加载失败时不保留空白占位           |
| 打开方式 | HTTP 与 HTTPS 来源均进入应用内原网页；其他协议不会进入来源列表       |

首屏约显示 3 条结果，其余来源在同一列表中滚动查看。列表必须保留原始排序、当前滚动位置和当前选择状态。关闭原网页或点击“返回搜索结果”后，恢复到离开前的滚动位置。

### 4.3 原网页与加载恢复

选择 HTTP 或 HTTPS 结果后，伴随窗在同一个隔离 `WebContentsView`（网页内容视图）中加载原页面。标题栏持续显示真实域名，并提供“返回搜索结果”“系统浏览器打开”和“关闭”。

标题栏在原网页的加载中、成功和失败状态下提供紧凑的布局预览切换器：左侧为电脑图标，右侧为竖版图标。默认选中竖版，选中图标使用蓝色高亮，未选中图标保持中性灰色；两个按钮分别提供“电脑布局”和“竖版布局”的悬停提示、无障碍名称、键盘焦点与按下状态。图标表达网页在当前外框中的排版宽度，不代表 iPad、Safari 或真实设备模拟。

原网页状态机为：

```text
搜索结果预览
  └─ 选择 HTTP 或 HTTPS 结果
      └─ 加载中
          ├─ 加载成功 → 原网页
          └─ 超时/失败 → 错误恢复页
                           ├─ 重试
                           ├─ 系统浏览器打开
                           └─ 返回搜索结果
```

失败状态必须保留所选结果的标题、域名和 URL 上下文，不能以无限白屏代替错误界面。远程网页的正文不与本地标题栏或错误恢复页共享 Node、Preload 或 IPC 权限。

伴随窗不显示产品自写的“百科摘要”“关键事实”“AI 结论”或与原站点混合的编辑内容。用户必须能够明确区分 AI 回答、搜索结果预览和源网页。

### 4.4 电脑与竖版布局预览

- `portrait`（竖版布局）是每次新打开来源预览时的默认模式，以 768 CSS 像素为排版基准，并整体缩放进现有竖版伴随窗。
- `desktop`（电脑布局）以 1280 CSS 像素为排版基准，同样缩放进现有竖版伴随窗，用于查看网页的桌面排版。
- 两种模式共用同一个隔离 `WebContentsView`。切换时只改变 Electron 官方网页缩放参数，不销毁视图、不重新加载页面、不改写 URL。
- 网页使用 Chromium 实际的 User-Agent 和输入能力；不得伪造 iPad/Safari User-Agent，不启用触控模拟、设备指标协议或调试器。
- 因页面不重载，当前会话、表单输入、播放状态和滚动位置自然保留；鼠标滚轮、点击、文本选择和键盘输入保持原生网页交互。
- 伴随窗拉伸后根据可用宽度重新计算缩放，网页内容填满标题栏下方区域，不额外绘制假的设备外壳。
- 布局切换只在原网页的加载中、成功和失败状态显示；搜索结果列表不显示，避免把“布局预览”误解为来源筛选。
- 用户在当前伴随窗内的选择可用于后续来源；关闭伴随窗或打开新一组搜索来源后恢复默认竖版布局。

### 4.5 当前实现限制

`prototypes/voice-chat-panel.html`（语音聊天面板原型）仍使用本地静态内容模拟百科源网页和搜索结果，只用于保留早期布局参考。正式方向的 `desktop/` 已实现单一来源入口、本地搜索结果列表，以及隔离 `WebContentsView` 的加载中、成功、HTTP 状态错误、网络失败、渲染失败和 15 秒超时状态。HTTP 与 HTTPS 来源均进入应用内网页视图，其他协议在进入桌面端前被丢弃。

## 5. 关键交互流程

### 5.1 语音对话

1. 用户展开头像悬浮球。
2. 用户首次按住“按住说话”时，界面显示“正在连接”，并请求麦克风权限、创建 LiveKit 本地音轨。
3. 轨道就绪后胶囊原位变蓝，显示“松开结束”和实时音量柱；后续按住复用同一音轨。
4. 用户松开后本地音轨立即静音；Room 继续接收 Agent 的转写、思考、回答状态和远端音频。
5. AI 回复以轻量气泡显示；若本轮搜索产生可展示来源，则在回复下显示一个“已检索 N 个网页来源”入口。

### 5.2 浏览搜索结果

1. 用户点击聊天回答下方的“已检索 N 个网页来源”。
2. 应用在聊天面板内侧打开伴随来源浏览窗。
3. 浏览窗显示查询词、实际来源数量和按原始排序排列的搜索结果预览。
4. 用户滚动查看全部来源；关闭窗口时保留聊天面板和对话滚动位置。

### 5.3 浏览原网页

1. 用户在搜索结果预览中选择一条 HTTP 或 HTTPS 来源。
2. 浏览窗显示真实域名和加载状态，并在同一隔离网页视图中加载对应源页面。
3. 加载成功后显示原站点页面；用户点击“返回搜索结果”时恢复列表原滚动位置。
4. 用户可通过电脑和竖版图标切换网页排版；首次进入默认使用竖版布局，切换时不重载页面，并保留当前 URL、会话、表单和滚动位置。
5. 页面超时或加载失败时保留结果标题、域名和 URL，提供重试、系统浏览器打开、返回搜索结果和关闭。
6. 对 `javascript:`、`file:`、`data:` 等非 HTTP(S) 结果，不创建远程网页视图，也不允许通过来源入口打开。

## 6. Windows 桌面端架构建议

### 6.1 技术选型

首期继续推荐 **Electron + React + TypeScript + Vite**：

- 现有 AI Agent 使用 Node.js 与 TypeScript，可减少桌面壳和 Agent 之间的语言与运行时边界。
- Electron 主进程负责透明置顶窗口、全局快捷键、系统托盘、位置尺寸持久化和 Agent 生命周期。
- React 渲染进程只负责本地可信界面，可以持有本地 `LocalAudioTrack` 和短期参与者 Token，但不直接持有搜索、LiveKit API Secret 或模型的长期密钥。
- 使用 Electron Forge、Electron Builder 或经过验证的等价工具生成 Windows 安装程序与 `.exe`；正式发布前需要代码签名规划。

Tauri 仍可作为未来评估项，但当前 Node Agent 仍需随应用运行，Tauri 的体积优势会缩小，同时会增加 Rust 和跨进程维护成本。

### 6.2 推荐进程与窗口分层

```text
Electron Main Process（主进程）
├─ Assistant BrowserWindow：透明置顶聊天窗口
│  ├─ Preload：只暴露白名单 IPC
│  └─ React Renderer：头像浮球、聊天气泡、语音状态、单一来源入口
├─ Source BrowserWindow：伴随来源窗口
│  ├─ Local React：搜索结果预览、加载/失败状态、返回、域名、外部打开与关闭
│  └─ WebContentsView：隔离加载经过校验的 HTTP(S) 源页面
└─ Node AI Agent：LiveKit、DeepSeek、豆包 STT/TTS、searchWeb
```

搜索结果列表由本地可信 React 页面根据 `searchWeb` 结构化结果渲染；真正的第三方源页面进入单独的 `WebContentsView`。本地主进程必须把远程网页的加载开始、成功、失败和超时状态转换为白名单 IPC 事件，来源 Renderer 只消费经过校验的状态与来源元数据。不使用已弃用的 `BrowserView`，也不把 `<webview>` 标签作为首选方案。

### 6.3 远程网页安全边界

第三方网页属于不可信内容，必须与本地应用能力隔离：

- 只允许 HTTP 与 HTTPS；拒绝 `file:`、`javascript:`、自定义命令协议和不受支持的 URL。
- 远程 `WebContentsView` 设置 `nodeIntegration: false`、`contextIsolation: true` 和 `sandbox: true`。
- 远程网页不加载应用 Preload，不获得 IPC、文件系统、剪贴板、麦克风、摄像头或通知权限。
- 使用 `setPermissionRequestHandler()` 默认拒绝远程页面权限请求。
- 使用 `will-navigate`、`will-redirect` 和 `setWindowOpenHandler()` 校验导航目标并阻止任意新窗口。
- 使用 URL 解析器校验协议、主机和来源策略，不能用字符串前缀判断可信域名。
- 所有来自本地 Renderer 的 IPC 都验证发送方；远程网页不能向主进程发送特权命令。
- 本地应用页面优先使用受控自定义协议，而不是生产环境中的 `file://`。

## 7. 状态与异常

| 状态           | 页面表现                                          |
| -------------- | ------------------------------------------------- |
| AI 正在回答    | 显示简短状态，不提前展示不完整来源入口            |
| 搜索成功       | 回答完成后显示一个“已检索 N 个网页来源”入口       |
| 无联网资料     | AI 明确说明未联网核实；不伪造来源入口或来源名称   |
| 部分来源异常   | 按条降级或剔除，保留其他有效来源，不整批失败      |
| 搜索预览       | 显示查询词和实际数量；首屏约 3 条，全部结果可滚动 |
| 源网页加载中   | 显示所选标题、真实域名和明确加载反馈              |
| 源网页加载失败 | 保留搜索结果上下文，显示返回、重试和安全外部打开  |
| 返回搜索结果   | 恢复列表原排序、滚动位置和当前选择状态            |
| 来源时间未知   | 显示“时间以原始页面为准”，不声称实时              |
| 麦克风连接中   | 胶囊原位显示连接状态，避免重复创建采集轨道        |
| 麦克风不可用   | 显示错误状态；再次按住可重新请求权限和创建轨道    |
| Agent 异常     | 头像或标题栏显示错误状态，并提供重试入口          |
| 游戏为独占全屏 | 提示切换无边框窗口模式；后台语音服务继续运行      |

## 8. 验收标准

- [x] Electron 收起窗口将原生拖动把手和 48px 头像点击区分离，并可吸附扩展屏左右边缘；重新展开时跟随悬浮球当前显示器、停靠侧和垂直位置，异常历史尺寸回退到设计默认值。
- [x] HTML 原型中的聊天面板可通过标题栏移动，并通过四边和四角直接拉伸。
- [x] HTML 原型中的来源卡片可打开独立百科源页面或搜索结果预览状态；仅作为早期交互参考。
- [x] Electron 来源浏览窗使用隔离的 `WebContentsView` 加载经过校验的 HTTP(S) 页面。
- [x] 来源浏览窗始终跟随聊天面板，收起聊天面板时同步关闭；完整窗口边界对象不得覆盖重新计算的伴随坐标。
- [x] 来源浏览窗创建时在构造参数中指定伴随坐标并延迟显示，避免聊天面板在扩展屏时来源窗先闪现在主屏再跳到伴随位置。
- [x] 多显示器负坐标、边缘吸附、向内展开和伴随窗口定位具有单元测试覆盖。
- [x] 按住说话使用可复用的 LiveKit 本地音轨，松开、窗口卸载时能够静音或停止并释放资源。
- [x] 激活态使用同一条麦克风音轨提供实时音量反馈，不使用随机或固定动画伪造输入。
- [x] 按住说话支持鼠标、触控笔、触摸和键盘，具有可见焦点与 `aria-pressed` 状态。
- [ ] 正式客户端支持全局快捷键和可选鼠标穿透。
- [x] 正式客户端支持窗口置顶与位置尺寸持久化。
- [x] 可信主进程签发短期参与者 Token，桌面 Renderer 不接触 LiveKit API Secret。
- [x] 桌面客户端连接 Room，在按住期间发布本地音轨，并订阅 Agent 返回的远端音频。
- [x] 正式客户端对权限、导航、新窗口、IPC 发送方和外部打开 URL 执行安全校验。
- [x] 同一条 Agent 回答下只显示一个“已检索 N 个网页来源”入口，`N` 等于清洗后实际可展示数量。
- [x] 点击来源入口先打开搜索结果预览，而不是直接打开第一条原网页；列表展示网站身份、标题、搜索摘要、可选缩略图和可用发布时间。
- [x] 单条脏来源不会导致整批来源入口消失；HTTP 与 HTTPS 来源均可进入应用内 `WebContentsView`。
- [x] 选择 HTTP 或 HTTPS 结果后可在原网页与搜索结果之间往返，返回时保留列表滚动位置。
- [x] 原网页加载具有加载中、成功、超时和失败状态；失败时不显示无限白屏，并提供返回、重试和系统浏览器打开。
- [x] 来源窗口标题栏显示当前真实域名，且加载状态与错误文案可被辅助技术读取。
- [x] 原网页标题栏显示电脑与竖版图标切换器，默认竖版使用蓝色选中态，搜索结果列表不显示该控件。
- [x] 竖版布局使用 768px 排版基准，电脑布局使用 1280px 排版基准；两者均缩放进同一竖版伴随窗。
- [x] 切换布局不重建或重载网页，不伪造 User-Agent，不启用触控模拟、设备指标协议或调试器。
- [x] 切换布局保持当前 URL、会话、表单与滚动位置；鼠标滚轮等原生输入继续作用于网页，拉伸窗口后重新适配。
- [ ] 1080p、1440p、4K 和超宽屏下，展开与拉伸后的窗口不遮挡屏幕中央关键区域。
- [ ] Windows 安装包完成麦克风、音频播放、LiveKit 连接、来源浏览和应用退出清理验证。
- [ ] 所有按钮、来源入口、搜索结果和主要窗口操作可通过键盘使用，并具有可见焦点状态。

## 9. 非目标

- 不实现直接注入游戏进程、读取游戏内存或绕过游戏窗口限制的原生 Overlay。
- 不承诺独占全屏模式下的置顶窗口显示；首期优先支持无边框窗口模式。
- 不在远程网页 Renderer 中暴露 Agent、密钥、文件系统或任意 Electron API。
- 不抓取和重新发布第三方网页全文；缓存与离线阅读需另立规格并评估版权与存储边界。
- 不在本期实现账号、支付、收藏、历史会话同步、多人协作或运营后台。

## 10. 待确认项

1. PTT、显示/隐藏和收起/展开的默认全局快捷键及冲突策略。
2. 搜索预览单次最多保留多少条清洗后来源；当前参考响应返回 10 条，供应商总召回数不作为界面数量。
3. 关闭伴随窗后再次打开时，是否恢复上次的尺寸、预览滚动位置和已选来源。
