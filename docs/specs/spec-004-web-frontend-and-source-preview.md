# Spec-004：桌面悬浮语音面板与来源浏览窗

**日期：** 2026-07-17

**状态：** Electron 桌面、LiveKit Room 接入和启动诊断已实现；安装包待开发

## 1. 背景

用户在《微软模拟飞行》中需要与 AI 导游持续语音对话，同时必须保留驾驶舱、地景和仪表的主要可视区域。普通聊天应用和直播间式界面占用面积过大，因此本功能采用可收起的悬浮语音面板。

当 AI 回答包含网页来源时，用户还需要快速判断来源是否值得阅读。来源内容不能挤入聊天窗口，也不能变成产品自行改写的百科卡片。因此使用独立的伴随来源浏览窗，显示源网页或搜索结果预览。

本规格不改变现有 LiveKit 语音 Agent、`searchWeb`（公开网页搜索工具）及其来源质量策略。

## 2. 需求边界

**包含：**

- 64×72px 收起窗口，包含独立原生拖动把手和 48px 头像点击区，并吸附到最近显示器的左侧或右侧边缘。
- 可移动、可收起、可从四边和四角拉伸的紧凑语音聊天面板。
- Discord/微信式轻量气泡，只保留最近对话、来源入口和按住说话操作。
- 基于 LiveKit `LocalAudioTrack` 的按住说话，以及来自同一音轨的实时音量反馈。
- AI 回答中的网页链接以紧凑来源卡片显示。
- 点击来源卡片后打开独立伴随浏览窗。
- 伴随浏览窗只提供“源网页”和“搜索结果预览”两类内容状态。
- 聊天面板与伴随浏览窗均限制在屏幕安全区域内。
- Windows 桌面壳及 `.exe` 打包架构建议。

**不包含：**

- 直播间式布局、弹幕、礼物、观众列表或持续占屏的角色立绘。
- 产品自建百科摘要、事实卡片、知识图谱或额外编辑内容。
- 多标签通用浏览器、收藏夹、下载管理、密码管理或浏览器扩展。
- Microsoft Flight Simulator 遥测、位置、航向、机场和航线数据。
- 正式 `.exe` 安装包、自动更新和代码签名。

## 3. 已确认的界面状态

| 状态           | 默认尺寸                       | 内容                                     | 行为                                                         |
| -------------- | ------------------------------ | ---------------------------------------- | ------------------------------------------------------------ |
| 头像悬浮球     | 收起窗口 64×72px；头像 48×48px | 导游头像                                 | 顶部把手拖动；头像点击展开；松开后吸附最近显示器的左/右边缘  |
| 语音聊天面板   | 默认 320×360px；最小 240×158px | 标题栏、最近对话、来源卡片、按住说话按钮 | 标题栏拖动；四边和四角拉伸；“收起”恢复头像悬浮球             |
| 伴随来源浏览窗 | 默认 440×600px；最小 280×240px | HTTPS 源网页                             | 始终出现在聊天面板内侧并跟随移动；可拉伸；关闭后保留聊天面板 |

### 3.1 头像悬浮球

- 收起后顶部显示 36×14px 可见拖动把手，下方显示 48px 头像，不显示额外文字按钮。
- 拖动把手使用 Electron 原生 `app-region: drag`；头像使用 `app-region: no-drag`，整个圆形区域点击后展开聊天面板。
- 拖动结束时保留垂直位置，只吸附到最近的左侧或右侧屏幕边缘。
- 显示器选择使用光标所在显示器或窗口覆盖显示器，必须正确处理负坐标、不同缩放比例和扩展屏排列。
- 点击展开时必须根据所在边缘向屏幕内侧展开，不能让面板主体出现在屏幕外。
- 展开、拖动和吸附使用同一位置状态，不能出现偶尔拖不动或收起后停在屏幕中央的情况。

### 3.2 语音聊天面板

- 标题栏仅保留头像、名称、在线/聆听状态和“收起”。
- 对话区使用轻量气泡；导游回复内容中不重复显示头像。
- 默认只保留当前一问一答，内容超过高度后在对话区内部滚动。
- “按住说话”使用固定 160×38px 紧凑胶囊，是唯一持续突出显示的主操作，不占满底栏宽度。
- 首次按住时申请麦克风权限并创建 LiveKit `LocalAudioTrack`；后续按住复用并恢复该轨道，松开后立即静音。
- 请求权限时显示“正在连接”，聆听时原位切换为蓝色“松开结束”状态，并显示 5 根随输入音量变化的柱条；错误时显示可重试的“麦克风不可用”。
- 不显示放大、还原等传统窗口按钮；用户直接拖动边框调整大小。

### 3.3 伴随来源浏览窗

- 与聊天面板是两个独立视觉窗口，来源内容不会扩张聊天面板本身。
- 初次打开时优先放在聊天面板靠屏幕中心的一侧；空间不足时切换到另一侧，并始终保留 16px 安全边距。
- 浏览窗始终跟随聊天面板移动、拉伸及跨显示器后的新位置。
- 用户尝试独立移动浏览窗时，主进程在移动结束后恢复到聊天面板旁的伴随位置，避免两个窗口分离。
- 四边和四角均为不可见拉伸热区，不显示右下角拉伸手柄。
- 收起聊天面板时同步关闭来源浏览窗，避免遗留大面积窗口遮挡游戏。

## 4. AI 回答与来源预览

### 4.1 聊天中的来源卡片

AI 回答包含有效 HTTP/HTTPS URL 时，在对应回复下显示来源卡片。卡片可包含：

| 字段     | 说明                                   |
| -------- | -------------------------------------- |
| 标题     | 源页面标题或可理解的降级标题           |
| 域名     | 明确显示来源站点身份                   |
| 简短说明 | 1-2 行说明来源与回答的关系，不代替原文 |
| 图片     | 来源提供的封面或缩略图；不可用时省略   |
| 操作     | 点击整张卡片打开伴随来源浏览窗         |

同一条回答中的重复 URL 只生成一张卡片。无效 URL、非 HTTP/HTTPS 协议或无法确认的链接不生成伪造预览。

### 4.2 伴随窗允许的内容

伴随窗只允许以下两种主内容：

1. **源网页：** 直接显示百科或其他被引用页面，保留域名、原站点排版和导航上下文。
2. **搜索结果预览：** 显示查询词、来源域名、结果标题、摘要和可用缩略图；首屏默认最多 3 条，其余内容通过滚动或后续加载查看。

伴随窗不显示产品自写的“百科摘要”“关键事实”“AI 结论”或与原站点混合的编辑内容。用户必须能够明确区分 AI 回答、搜索结果和源网页。

### 4.3 当前原型限制

`prototypes/voice-chat-panel.html`（语音聊天面板原型）仍使用本地静态内容模拟百科源网页和搜索结果，只用于保留早期布局参考。正式方向的 `desktop/` 实现已经通过 Electron `WebContentsView` 加载经过校验的 HTTPS 源网页，并接入 LiveKit Room、真实 Agent 转写/来源、麦克风发布、回答音频与连接诊断；搜索结果列表和正式加载错误界面仍待完善。

## 5. 关键交互流程

### 5.1 语音对话

1. 用户展开头像悬浮球。
2. 用户首次按住“按住说话”时，界面显示“正在连接”，并请求麦克风权限、创建 LiveKit 本地音轨。
3. 轨道就绪后胶囊原位变蓝，显示“松开结束”和实时音量柱；后续按住复用同一音轨。
4. 用户松开后本地音轨立即静音；Room 继续接收 Agent 的转写、思考、回答状态和远端音频。
5. AI 回复以轻量气泡显示；若包含来源，则在回复下显示来源卡片。

### 5.2 浏览百科源页面

1. 用户点击聊天中的百科来源卡片。
2. 应用在聊天面板内侧打开伴随来源浏览窗。
3. 浏览窗显示原始域名和源网页。
4. 用户可拖动标题栏、拉伸任一边框，或点击返回/关闭回到纯聊天状态。

### 5.3 浏览搜索结果

1. 用户点击“查看 N 条网页搜索结果”。
2. 伴随来源浏览窗切换为搜索结果预览。
3. 用户选择某条结果后，浏览窗在同一隔离网页视图中加载对应源页面。
4. 页面加载失败时保留结果信息，并提供重试或经安全校验后在系统浏览器打开的操作。

## 6. Windows 桌面端架构建议

### 6.1 技术选型

首期继续推荐 **Electron + React + TypeScript + Vite**：

- 现有 AI Agent 使用 Node.js 与 TypeScript，可减少桌面壳和 Agent 之间的语言与运行时边界。
- Electron 主进程负责透明置顶窗口、全局快捷键、系统托盘、位置尺寸持久化和 Agent 生命周期。
- React 渲染进程只负责本地可信界面，可以持有本地 `LocalAudioTrack` 和短期参与者 Token，但不直接持有搜索、LiveKit API Secret 或模型的长期密钥。
- 使用 Electron Forge、Electron Builder 或经过验证的等价工具生成 Windows 安装程序与 `.exe`；正式发布前需要代码签名规划。

Tauri 仍可作为未来评估项，但当前 Node Agent 仍需随应用运行，Tauri 的体积优势会缩小，同时会增加 Rust 和跨进程维护成本。

### 6.2 推荐进程与窗口分层

```text
Electron Main Process（主进程）
├─ Assistant BrowserWindow：透明置顶聊天窗口
│  ├─ Preload：只暴露白名单 IPC
│  └─ React Renderer：头像浮球、聊天气泡、语音状态、来源卡片
├─ Source BrowserWindow：伴随来源窗口
│  ├─ Local Chrome：返回、域名、关闭、拖动与拉伸
│  └─ WebContentsView：隔离加载经过校验的 HTTPS 源页面
└─ Node AI Agent：LiveKit、DeepSeek、豆包 STT/TTS、searchWeb
```

搜索结果列表可由本地可信 React 页面根据 `searchWeb` 结构化结果渲染；真正的第三方源页面进入单独的 `WebContentsView`。不使用已弃用的 `BrowserView`，也不把 `<webview>` 标签作为首选方案。

### 6.3 远程网页安全边界

第三方网页属于不可信内容，必须与本地应用能力隔离：

- 只允许 HTTPS；拒绝 `file:`、`javascript:`、自定义命令协议和不受支持的 URL。
- 远程 `WebContentsView` 设置 `nodeIntegration: false`、`contextIsolation: true` 和 `sandbox: true`。
- 远程网页不加载应用 Preload，不获得 IPC、文件系统、剪贴板、麦克风、摄像头或通知权限。
- 使用 `setPermissionRequestHandler()` 默认拒绝远程页面权限请求。
- 使用 `will-navigate`、`will-redirect` 和 `setWindowOpenHandler()` 校验导航目标并阻止任意新窗口。
- 使用 URL 解析器校验协议、主机和来源策略，不能用字符串前缀判断可信域名。
- 所有来自本地 Renderer 的 IPC 都验证发送方；远程网页不能向主进程发送特权命令。
- 本地应用页面优先使用受控自定义协议，而不是生产环境中的 `file://`。

## 7. 状态与异常

| 状态           | 页面表现                                          |
| -------------- | ------------------------------------------------- |
| AI 正在回答    | 显示简短状态，不提前展示不完整来源卡片            |
| 无联网资料     | AI 明确说明未联网核实；不伪造来源卡片             |
| 来源卡解析失败 | 保留经过校验的原始链接和“无法生成预览”提示        |
| 源网页加载失败 | 保留搜索结果上下文，显示重试或安全外部打开操作    |
| 多个来源       | 按回答中的出现顺序展示；搜索结果首屏默认最多 3 条 |
| 来源时间未知   | 显示“时间以原始页面为准”，不声称实时              |
| 麦克风连接中   | 胶囊原位显示连接状态，避免重复创建采集轨道        |
| 麦克风不可用   | 显示错误状态；再次按住可重新请求权限和创建轨道    |
| Agent 异常     | 头像或标题栏显示错误状态，并提供重试入口          |
| 游戏为独占全屏 | 提示切换无边框窗口模式；后台语音服务继续运行      |

## 8. 验收标准

- [x] Electron 收起窗口将原生拖动把手和 48px 头像点击区分离，并可吸附扩展屏左右边缘后向内展开。
- [x] HTML 原型中的聊天面板可通过标题栏移动，并通过四边和四角直接拉伸。
- [x] HTML 原型中的来源卡片可打开独立百科源页面或搜索结果预览状态。
- [x] Electron 来源浏览窗使用隔离的 `WebContentsView` 加载经过校验的 HTTPS 页面。
- [x] 来源浏览窗始终跟随聊天面板，收起聊天面板时同步关闭。
- [x] 多显示器负坐标、边缘吸附、向内展开和伴随窗口定位具有单元测试覆盖。
- [x] 按住说话使用可复用的 LiveKit 本地音轨，松开、窗口卸载时能够静音或停止并释放资源。
- [x] 激活态使用同一条麦克风音轨提供实时音量反馈，不使用随机或固定动画伪造输入。
- [x] 按住说话支持鼠标、触控笔、触摸和键盘，具有可见焦点与 `aria-pressed` 状态。
- [ ] 正式客户端支持全局快捷键和可选鼠标穿透。
- [x] 正式客户端支持窗口置顶与位置尺寸持久化。
- [x] 可信主进程签发短期参与者 Token，桌面 Renderer 不接触 LiveKit API Secret。
- [x] 桌面客户端连接 Room，在按住期间发布本地音轨，并订阅 Agent 返回的远端音频。
- [x] 正式客户端对权限、导航、新窗口、IPC 发送方和外部打开 URL 执行安全校验。
- [ ] 1080p、1440p、4K 和超宽屏下，展开与拉伸后的窗口不遮挡屏幕中央关键区域。
- [ ] Windows 安装包完成麦克风、音频播放、LiveKit 连接、来源浏览和应用退出清理验证。
- [ ] 所有按钮、来源卡片和主要窗口操作可通过键盘使用，并具有可见焦点状态。

## 9. 非目标

- 不实现直接注入游戏进程、读取游戏内存或绕过游戏窗口限制的原生 Overlay。
- 不承诺独占全屏模式下的置顶窗口显示；首期优先支持无边框窗口模式。
- 不在远程网页 Renderer 中暴露 Agent、密钥、文件系统或任意 Electron API。
- 不抓取和重新发布第三方网页全文；缓存与离线阅读需另立规格并评估版权与存储边界。
- 不在本期实现账号、支付、收藏、历史会话同步、多人协作或运营后台。

## 10. 待确认项

1. PTT、显示/隐藏和收起/展开的默认全局快捷键及冲突策略。
2. 每条 AI 回答默认显示的来源卡片数量上限。
3. 来源站点允许策略是“仅 HTTPS + 风险拦截”，还是增加明确域名白名单。
4. 关闭伴随窗后再次打开时，是否恢复上次的尺寸。
