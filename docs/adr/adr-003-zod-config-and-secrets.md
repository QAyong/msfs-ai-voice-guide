# ADR-003：Zod 边界校验与密钥管理

**日期：** 2026-07-15  
**状态：** 已接受

## 背景

实时 Agent 依赖多个连接地址、凭据和模型配置。未经校验的环境变量会把配置错误推迟为难以诊断的运行时故障，且日志与文档中的密钥泄漏风险不可接受。

## 决策

使用 Zod Schema 在进程启动时集中解析所有环境配置；未来每个业务工具的外部输入也使用 Zod Schema 校验。所有密钥只从运行环境或本地未提交的环境配置文件读取。

## 原因

Zod 同时提供运行时校验与 TypeScript 类型推导，避免手写重复校验器。集中配置保证错误在连接服务之前失败，并使 Provider 切换的配置边界清晰。

## 影响

- 禁止在业务模块中散落读取 `process.env`；只能通过 `src/config/` 导出的已校验配置访问。
- `.env`、`.env.local` 和任何包含真实密钥的文件必须被 `.gitignore` 排除；只提交 `.env.example`。
- 错误消息可报告变量名和格式问题，不得输出值、认证 Header 或完整连接字符串中的敏感部分。
- 所有未来工具在调用前必须用其 Zod 参数 Schema 解析输入；解析失败时不执行副作用。

## 不在此决策范围内

- 选择哪种第三方密钥管理服务。
- 用户身份、权限模型与密钥轮换流程。
- 开发机器以外的部署配置。
