# ADR-004：火山引擎作为第一版唯一 Provider 基线

**日期：** 2026-07-15  
**状态：** 已接受

## 背景

第一版已确定使用火山引擎，而参考项目 `Pipecat-AI` 已形成按 STT/LLM/TTS 分层、集中 Provider 注册表和启动前自检的可维护实践。原先“供应商待定”的决策已不再适用。

## 决策

第一版固定使用火山方舟 LLM、豆包流式 ASR 和豆包双向流式 TTS；以按能力分类的 `src/providers/registry.ts`（Provider 工厂注册表）作为唯一装配入口。LLM 优先复用 LiveKit 官方 OpenAI 兼容插件，STT/TTS 仅在当前官方插件不存在时实现受限于 Provider 层的最小适配器。

## 原因

统一供应商能快速完成本地语音闭环；复用参考项目已经验证的职责边界，能避免把鉴权、协议和模型参数散落在 Agent 入口。优先采用 LiveKit 已有插件，满足“不重复造轮子”的约束。

## 影响

- 第一版的 Zod Schema 与 `.env.example` 必须包含方舟、豆包 STT、豆包 TTS 所需配置及凭据组合校验。
- 所有 Provider 创建经 `registry.ts` 完成；Agent、提示词、未来工具模块不可直接导入火山 SDK 或连接 WebSocket。
- 新 Provider 仍按 STT/LLM/TTS 子目录新增工厂并注册；不能修改现有调用方分支判断。
- 每次安装或升级依赖时，先检查 LiveKit 当前官方插件是否已提供火山原生支持；若已提供，应替换自定义适配器并保留注册表边界。
- 密钥继续只从 `.env`/环境变量读取；不采用参考项目可保存密钥的 `settings.json` 方案。

## 不在此决策范围内

- 火山模型、资源 ID、音色和区域端点的最终产品选型。
- 多 Provider 运行时切换、回退与成本路由。
- 模拟器遥测或 MCP 工具调用。
