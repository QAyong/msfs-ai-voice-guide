# ADR-007：通过项目记忆服务边界接入 Mem0

**日期：** 2026-07-19

**状态：** 已接受，待实施

## 背景

LiveKit Agents 已经维护当前 `AgentSession`（Agent 会话）的完整聊天上下文，但默认不会在新 Session 中恢复过去的用户偏好和飞行经历。项目计划使用 Mem0 增加跨会话长期记忆。

如果 Agent 入口、提示词或桌面 UI 直接调用 Mem0 SDK，记忆供应商、实时语音生命周期和产品保存策略会耦合在一起，后续难以测试、切换本地/托管部署或替换实现。Mem0 也不能取代 LiveKit 当前会话历史、DeepSeek 主对话模型或 `searchWeb` 外部事实检索。

## 决策

项目通过自有的 `src/memory/`（记忆服务模块）边界接入 Mem0。LiveKit `ChatContext` 继续负责当前 Session 上下文；Mem0 只负责跨 Session 长期记忆；`searchWeb` 继续负责公开网页事实检索。

业务模块只依赖 `MemoryService`（记忆服务接口）。Mem0 SDK 或 HTTP API 只能出现在 Mem0 适配器中。Agent 入口负责依赖装配，不直接实现记忆存储、Embedding（向量嵌入）或检索协议。

记忆服务是可选依赖并采用 fail-open（失败后继续）策略：超时、认证失败或存储不可用时，当前语音对话必须按“没有长期记忆”继续运行。

## 原因

- LiveKit 已经可靠维护当前会话历史，无需用第三方框架重复实现。
- Mem0 专注长期记忆提取和语义检索，可避免项目自行建设记忆算法与向量基础设施。
- 项目边界能让单元测试使用内存测试替身，不依赖真实第三方 Key 或网络。
- 隔离适配器后，可以在不改变 Agent 会话策略的情况下评估 Mem0 OSS、Mem0 Platform 或未来替代方案。
- 将用户记忆与网页搜索结果分开，可以防止临时天气、新闻和网页内容污染用户画像。
- fail-open 策略符合实时语音优先目标；辅助记忆故障不应中断 STT、LLM 或 TTS 主链路。

## 影响

- 未来新增 `src/memory/`，负责类型、策略、预算、脱敏和供应商无关接口。
- Mem0 依赖不得散落在 `src/agent/`、`src/conversation/`、`src/tools/` 或 `desktop/` 中。
- `src/agent/` 只在官方会话钩子中组合检索和写入流程。
- Mem0 配置和密钥必须进入 `src/config/` 的 Zod（运行时 Schema 校验库）边界。
- 记忆检索结果必须按不可信数据处理，不能覆盖提示词或权限策略。
- 未经单独隐私与部署决定，不默认启用新的第三方云端记忆上传。
- 每个写入、纠正、删除、隔离和失败降级不变量都需要自动化测试。

## 不在此决策范围内

- 不在本 ADR 中确定 Mem0 OSS 或 Mem0 Platform。
- 不确定具体 Mem0、记忆提取 LLM、Embedding 或向量存储版本；实施时以锁文件和官方文档为准。
- 不确定桌面端记忆管理界面的交互设计。
- 不引入账号系统、多人共享记忆、跨设备同步或模拟器遥测。
- 不把 Mem0 选型解释为永久不可替换；不可违反的是项目记忆服务边界和职责分离。
